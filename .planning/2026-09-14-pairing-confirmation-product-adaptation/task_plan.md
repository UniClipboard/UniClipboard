# Task Plan: Pairing Confirmation Product Adaptation

## Goal
让 Desktop 使用 Engine 新增的配对确认状态，在设备界面准确展示等待确认和未被确认，确认完成后恢复正常连接状态，并让状态变化自动刷新；未被确认的设备继续使用现有移除流程。

## Completion Standard
- daemon 的公开设备结果完整携带 Engine 配对确认状态，OpenAPI 与前端类型一致。
- WebSocket 设备状态通知能使前端取得新状态，重复或乱序刷新不覆盖较新结果。
- 用户界面能区分等待确认和未被确认，已确认设备恢复正常连接展示；未被确认设备可使用现有移除动作。
- 不在 Desktop 复制 Engine 的期限、确认或撤销规则。
- 本地 Engine override 只用于开发验证，不把机器路径提交为正式依赖。
- 定向 Rust/前端测试、类型检查、格式、lint、构建和仓库门禁通过。
- 严格代码审查无阻塞问题；创建一个本地提交，不推送。

## Test Seams
- daemon 对外设备查询和设备状态变更事件。
- 前端设备状态上下文及用户可见设备列表。

## Phases
- [completed] 盘点现有改动、Engine 新合同、daemon DTO 和界面入口
- [completed] 先补公开边界失败测试，再贯通 daemon 与前端类型
- [completed] 实现配对状态展示、到期结束、自动刷新和现有移除动作
- [completed] 运行定向测试、完整前端测试与生产构建；实际窗口检查因当前会话没有浏览器控制能力而跳过
- [completed] 运行仓库门禁并做严格代码审查；全仓 lint 仅剩与本次无关的既有问题，变更文件 lint 通过
- [completed] 已固定到包含新合同的公开 Engine 版本，清理临时依赖覆盖并完成正式依赖复验
