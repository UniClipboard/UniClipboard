# PR #2180 审查修复

## 核对与决定

五项意见在当前源码中均成立。Decision: accept。

1. 资源验收的 finally 串行执行清理；恢复信号、进程等待或摘要读取抛错会阻断后续步骤，并丢失 result.json。
2. Quick Panel 声明 quick-panel，但内容锁列表仅有 gui/helper，导致该界面会话绕过界面内容授权。
3. 导入器的本地指标轮询使用默认代理配置，代理可能拦截 loopback 请求。
4. Collector 版本探测没有超时，启动与退出失败暴露 traceback。
5. TemporaryDirectory 先清理，外层 finally 才停止 Collector，运行中的接收器可能失去输入和配置文件。

## 修改前的失败清单与验证计划

- 恢复 daemon 失败后，仍尝试关闭测试子进程、停止 daemon、读取所有二进制摘要并写回执。
- 二进制不可读或不存在时，保留失败条目和其他二进制摘要，不把缺失文件筛掉。
- 清理失败不能把验收标为通过，也不能覆盖原场景异常。
- 版本命令卡住、路径不存在、非零退出分别返回有限时长的参数错误。
- 故意配置不可用的 HTTP 代理时，本地 Collector 指标轮询仍能工作。
- 成功导入及后端拒绝时，都在临时输入和配置仍存在时停止 Collector。
- 真实 daemon 中，quick-panel 与 gui 会话在内容授权撤销后收到 content_locked；解锁后可读取；CLI 语义保持不变。
- 使用真实产品负载和测试侧故障注入，不增加生产测试参数，不新增单元测试。
