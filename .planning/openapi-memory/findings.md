# 证据

原有utoipa-swagger-ui 7.1.0的axum适配器将拥有完整OpenAPI对象的闭包注册到routing::get；闭包和路由克隆触发深拷贝。上轮分配栈中的HTTP类别约4.29MiB，以OpenAPI对象复制为主。

当前基准为Desktop v1.3.0，与旧诊断版分开测量。保留ApiDoc唯一来源、现有两个文档URL和debug_assertions门控；Swagger通过Config指定URL，文档内容由Desktop文档路由负责提供。

方案：一次序列化为Bytes，路由闭包捕获共享的序列化结果，响应只克隆Bytes。序列化错误仍通过500响应可观测，不引入无声回退或修改文档契约。

优化版release文档响应与基准318,018字节JSON逐字节相同。发布版开发文档404、Swagger页面/初始化脚本与HEAD检查均通过。

首次文档访问前后观察：基准PSS约51.57→67.72MiB；共享响应版约50.18→50.19MiB。说明这轮收益不仅是文档对象本身的存活量，还包括访问时大量短命分配造成的分配器保留；完整100张/120秒静置结果见下方，不单独以阶段数据作为最终验收。

最终同负载对照确认PSS差17.22MiB，其中匿名PSS 40.09→22.97MiB，文件PSS约31.84→31.75MiB。收益主要体现于匿名内存，不由链接参数或调试符号裁剪制造。仅本机单轮对照，不保证所有平台同等收益，未验证真实双设备吞吐和24小时运行。

问题类型：结构性生命周期/所有权问题。原完整schema树被可克隆处理器持有；现在由专属文档路由负责一次序列化，Swagger只配置URL。删除原对象持有路径，无长期双轨逻辑，不扩展Engine接口或持久化缓存。
