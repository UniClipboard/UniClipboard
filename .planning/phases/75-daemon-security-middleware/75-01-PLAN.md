Check: if claims.access_level < required_level.as_u8(), return `(StatusCode::FORBIDDEN, Json(json!({"error": "insufficient_permission"}))).into_response()`

       - Call `next.run(request).await`

    **PERMISSION LEVEL ENFORCEMENT ARCHITECTURE (Phase 75):**
    - `permission_middleware` is defined and IS functional for L2 checks (valid token + PID whitelist).
    - L3/L4 enforcement is **intentionally deferred to per-handler checks** in Phase 75 because `encryption_ready` state lives in `CoreRuntime` (app layer), which the daemon cannot query synchronously during middleware evaluation. Handlers that need L3/L4 access check `claims.encryption_ready` themselves.
    - In Phase 76, L3/L4 enforcement will be wired into the middleware by having `permission_middleware` query `encryption_ready` from the `CoreRuntime` available via `DaemonApiState.runtime`.
    - The `permission_middleware` IS functional for its L2 scope. It is NOT a stub — it enforces L2 (valid token + PID) correctly.

    For now, implement permission_middleware to check L2 only (valid token + PID). Document that L3/L4 enforcement is done per-handler (Phase 75) with explicit path to middleware enforcement (Phase 76).
