# Brief: History Morphing Search

**日期：** 2026-09-04
**状态：** Locked
**完成日期：** 2026-09-06
**调研问题：** History 页如何采用 beUI Morphing Search 的连续形变体验，同时保留现有搜索能力。

## 建议

保留 History 现有的正文搜索、五类筛选、建议、快捷键和会话恢复，只替换展示层。顶栏右侧的 32×32 搜索按钮打开后，从原位置向左、向下展开为同一块玻璃搜索面板。

## 约束

- 展开面板位于顶栏筛选图标上方；向左展开时覆盖图标，收起后图标原样露出。
- 筛选图标始终留在原位，不能被移除、挪动或引发顶栏重新排版。
- 顶部 X 同时清空查询和全部筛选，并关闭面板；Esc 或点击外部只关闭、不清空。
- 结果数量放在顶部 X 左侧，不保留独立的“搜索与筛选 / 结果 / 清除全部”行。
- 继续支持 Cmd/Ctrl+F、`/`、`、`、Escape、上下键、Enter、Tab 和退格操作。
- 打开后聚焦输入框；关闭后焦点回到搜索按钮。
- 浅色、深色和窄窗口都必须正常；Windows/Linux 低特效模式下使用不透明表面且无动画。
- 不增加依赖，不引入第二套搜索状态。

## 验收标准

- 点击或使用快捷键后，搜索图标连续展开成一块搜索表面。
- 展开时筛选图标被自然遮住，没有穿透、错位或顶栏跳动。
- Esc 或点击外部收起后，筛选图标原样恢复；再次打开时查询和筛选仍在。
- 点击顶部 X 后查询和全部筛选被清空，同时面板关闭。
- 面板不超出窗口，所有现有搜索操作继续可用。

## 已排除方案

- 直接使用 beUI 原组件：它只过滤静态项目，关闭时清空内容，并且默认向右展开。
- 只给旧浮层增加玻璃背景：仍然是输入框和浮层分离，不符合连续形变要求。
- 重写搜索：没有必要，会给已稳定的搜索行为增加风险。

- 已在桌面应用实际检查展开覆盖关系，并根据实际截图统一搜索按钮形状与图标颜色。
