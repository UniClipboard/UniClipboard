# 调研简报：Windows `Win+V` 快捷键接管

**日期：** 2026-08-17
**状态：** 建议待确认
**问题：** 如何让 UniClipboard 的快捷面板使用 `Win+V`，并符合 Windows 的正常做法？

## 建议

如果需求的含义是“无论系统剪贴板历史是否开启，都让 `Win+V` 打开 UniClipboard”，则需要 Windows 专属的输入拦截能力；普通快捷键登记做不到。它应是一个明确标注风险、默认关闭的独立开关，而不是普通快捷键录制器中的任意组合。

保守方案仍可保留：只尝试普通登记，失败时引导用户自行关闭 Windows 剪贴板历史。这不满足“直接接管”，但维护成本低。

## 关键结论

1. `Win+V` 是 Windows 剪贴板历史的默认入口，且 Windows 把带 Windows 键的组合定义为系统保留快捷键。
2. 项目现有依赖走 Windows 的正式快捷键登记接口；当 `Win+V` 被占用，登记会失败。它适合普通组合，但不能完成真正的“接管”。
3. 当前快捷键录制器已可录入 `Win+V`，因此不需要新增另一套快捷键引擎或底层输入拦截。
4. AutoHotkey 和 PowerToys 一类工具会通过 Windows 的低层键盘监听在系统处理前截住组合键；这可以实现接管，但需要专门的 Windows 输入状态机和可靠性保护。

## 实施方案

### 真正接管（满足 Issue 原意）

- 新增 Windows 专属、默认关闭的“接管 `Win+V`”开关。
- 在专用 Windows 线程监听键盘，只在完整识别到 `Win+V` 时阻止系统继续处理，并把打开快捷面板的请求转回应用主线程。
- 对按下与松开、左右 Windows 键、Windows 键单独按下后弹出开始菜单、输入法、模拟按键、应用退出和开关切换建立状态机与测试。
- 监听线程只做识别和转发，不能做耗时工作；Windows 超时后会静默移除监听。
- 该模式启用时，普通 `Win+V` 登记不再参与；关闭或不支持时，回到原有快捷键配置。

### 保守方案（不接管系统）

- 继续使用现有的 Windows 全局快捷键登记。
- 利用现有的失败回滚：新组合登记不成功时，旧组合仍可用，设置不会被错误写入。
- 在 Windows 快捷键设置中说明用户可自行关闭系统剪贴板历史后重试。

### 不使用的方案

- 不由应用静默关闭 Windows 剪贴板历史：这是用户的系统级偏好，且可能受企业策略管理。
- 不把 `Win+V` 设为默认值：多数 Windows 用户的系统功能仍会占用它。

## 约束

- 输入拦截只在当前登录桌面生效，不能覆盖安全桌面等 Windows 隔离场景。
- 监听线程若处理超时，Windows 会移除它且不会通知应用；必须将工作压缩到最小并有可观测的恢复策略。
- 输入法、远程桌面、游戏反作弊和企业安全软件可能改变结果；必须按实际 Windows 机器验证。
- 保持 macOS 和 Linux 行为不变。
