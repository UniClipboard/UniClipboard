# CLI 生命周期失败模式与验收计划

实现前记录：

- 前台进程提前失败、退出码丢失、标准错误不可见、Ctrl-C/SIGTERM 未到达 daemon。
- 已有 GUI、standalone、oneshot、健康超时或版本不兼容 daemon 被误杀或重复启动。
- PID 文件先于连接文件发布；并发启动之间的检查存在竞态，最终仍受 daemon 单例规则约束。
- 服务未注册、注册但未加载、运行但 HTTP 不健康、其他 daemon 的 HTTP 被误认为服务健康。
- 重复安装/启动/停止、注册内容变化、原生管理器不可用、配置路径被其他文件占用。
- 用户路径含空格/XML 字符/systemd 转义字符，profile 不安全，服务命名碰撞。
- 登录后环境丢失、开发模式或 HOME/XDG 不同、系统钥匙串锁定、日志目录不存在。
- 临时构建路径失效、便携模式路径不同、生产服务引用工作树、root 安装误写全局服务。
- Rebase 验收：共享路径库的便携请求失败不能被当作非便携模式，必须在安装服务前拒绝。
- 停止和重启误操作非本命令创建的服务，健康探测意外启动 daemon。
- macOS 注销/登录、Linux 用户管理器退出/重启，与开机无需登录是不同语义。
- Windows 服务命令须拒绝，其他命令保持可构建。

验收：使用 isolated_env 创建唯一 HOME/profile、文件密钥存储与禁用系统剪贴板。先验证真实 daemon
前台生命周期和已有进程拒绝，再验证唯一 launchd 服务的安装、重复启动、状态、重启、停止、
重复停止、HTTP 失败、profile 隔离及旧 start 警告。最后 bootout 并移除本任务 plist，保留命令输出、
配置、二进制哈希与清理证据。Linux 缺少真实 systemd 时仅报告交叉编译，不能称运行验收。
