---
title: Advanced configuration
description: Environment variables for isolated profiles, headless nodes, networking, and diagnostics.
---

Most users should use command options and app settings instead of environment
variables. The variables below are the supported exceptions for deployment and
troubleshooting. Set them before starting `uniclip` or the desktop app.

## Isolated profiles

| Variable     | Effect |
| ------------ | ------ |
| `UC_PROFILE` | Select a named, isolated profile. It is equivalent to `--profile <NAME>` and separates data, secure-storage entries, logs, and network identity. |

For example:

```bash
UC_PROFILE=test uniclip space status
```

The desktop app and CLI can normally share the default profile. Use another
profile only when you deliberately need an independent instance.

## Headless nodes

Use the public command for a server that should not access the system
clipboard:

```bash
uniclip start --server
```

Linux without `DISPLAY` or `WAYLAND_DISPLAY` also disables clipboard access
automatically. To force the same behavior in a graphical session, set:

```bash
UC_DISABLE_SYSTEM_CLIPBOARD=1 uniclip start
```

## Direct-connection networking

| Variable              | Effect |
| --------------------- | ------ |
| `UC_IROH_BIND_PORT`   | Pin the local iroh UDP socket to one port instead of an ephemeral port. |
| `UC_IROH_PUBLIC_ADDR` | Advertise a known public `IP:port` as a direct-connection candidate. Usually paired with `UC_IROH_BIND_PORT`. |

These are deployment controls for a static NAT or firewall setup, not required
for normal pairing. See [Self-host a server node](../guides/self-host-server-node)
for the complete firewall and public-address setup.

## Diagnostic logging

For normal troubleshooting, prefer the public commands:

```bash
uniclip debug on
uniclip debug status
uniclip debug export-logs
uniclip debug off
```

`RUST_LOG` is available for a short, targeted session when support or a
developer asks for a specific filter:

```bash
RUST_LOG=debug uniclip start --foreground
```

Verbose logging still applies mandatory privacy limits. Do not leave a very
broad filter enabled longer than necessary.

Internal process-role, daemon-spawn, and development variables are intentionally
not listed here. They are implementation contracts, not user configuration.
