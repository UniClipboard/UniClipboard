`uniclip` is the terminal client for UniClipboard. It connects to the same
background service as the desktop app, so the CLI and GUI can use the same
profile and space. If a command needs the service and it is not running,
`uniclip` starts the matching `uniclipd` automatically.

If `uniclip --version` does not work yet, start with
[Install the CLI](./installation).

## Global options

These options work with every public command:

| Option             | Effect                                                               |
| ------------------ | -------------------------------------------------------------------- |
| `--json`           | Return machine-readable JSON for scripts.                            |
| `-v`, `--verbose`  | Show more diagnostic output in the terminal.                         |
| `--profile <NAME>` | Use an isolated data set, secure-storage entry, and network identity. |

You do not need a separate profile just because the desktop app is open. Use
`--profile` only when you intentionally want an independent instance, such as
two test devices on one computer.

## Create or join a space

<Tabs items={['First device', 'Join an existing space']}>

<Tab value="First device">

Create a space, then issue an invitation for another device:

```bash
uniclip space init
uniclip space invite
```

Both commands guide you through the required input. Treat the invitation as a
short-lived secret and use it only once.

</Tab>

<Tab value="Join an existing space">

Run the join command on the new device. You can paste the invitation when
prompted:

```bash
uniclip space join
```

For a non-interactive command, pass it explicitly:

```bash
uniclip space join --code <INVITATION_CODE>
```

The command also asks for the space passphrase and waits for the final result.
After it succeeds, check the member list:

```bash
uniclip member list
```

</Tab>

</Tabs>

Use `--no-wait` when a script should return after the join request is accepted.
You can then inspect or cancel that request:

```bash
uniclip space join status
uniclip space join cancel
```

Pressing Ctrl-C stops only the local wait; it does not cancel the request.

## Send and read content

```bash
# Send text to online paired devices
uniclip send "hello from the CLI"

# Send an existing regular file (auto-detected)
uniclip send ./report.pdf

# Force an existing filename to be sent as text
uniclip send --text report.pdf

# Read text from standard input
printf 'hello from a pipe' | uniclip send

# Print the newest already-synced text or link
uniclip get

# Wait for the next synced entry, then print it and exit
uniclip get --wait

# Wait for the next entry and copy it through the active terminal
uniclip get --copy --wait

# List recent entries without downloading one
uniclip get --list -n 20

# Search history
uniclip search "report"
```

By default, `get` returns content that is already in local history without
waiting. `get --wait` handles one new delivery and exits. `watch` prints all
future deliveries until you press Ctrl-C:

```bash
uniclip watch
```

The watcher is an observer; it does not write content into the system
clipboard.

## Send or receive a file

```bash
# Explicitly force file mode
uniclip send --file ./report.pdf

# Read complete file paths from stdin, one per line
printf '%s\n' ./report.pdf './images/cover art.png' | uniclip send --file

# Wait for the next incoming entry; files are saved under ./inbox
uniclip get --wait --out ./inbox
```

Existing regular files are detected automatically. File sending is owned by the
daemon, and the command exits after all relevant targets reach a terminal state.
When `-f` / `--file` has no positional path, stdin is a list of file paths, not
file contents. Blank lines are ignored, paths are validated before sending, and
duplicate paths are sent once. Use repeatable `--peer` flags to restrict the
targets; Ctrl-C cancels the wait.

## Manage the background service

Most commands start the service when needed. Use these commands when you want
explicit lifecycle control:

| Command                      | Effect                                                                 |
| ---------------------------- | ---------------------------------------------------------------------- |
| `uniclip start`              | Start `uniclipd` in the background.                                    |
| `uniclip start --foreground` | Keep it in the terminal and show its logs.                             |
| `uniclip start --server`     | Start a headless node without reading or writing the system clipboard. |
| `uniclip stop`               | Stop the service for the active profile.                               |
| `uniclip space status`       | Show service, space, network, and trust status.                        |

The desktop app and CLI reuse the same service when they use the same profile.
You should not launch `uniclipd` directly.

## Use the CLI in scripts

Add `--json` when another program consumes the result:

```bash
uniclip --json space status
uniclip --json member list
uniclip --json search "report" --limit 10
```

Human-readable status messages go to standard error where commands need to
keep standard output clean. Scripts should use JSON and the command's exit
status instead of matching terminal wording.

## Switch or rebuild a space

Switching to a different space migrates readable local history to the new
space:

```bash
uniclip space join --switch --code <NEW_INVITATION_CODE>
```

The command asks for confirmation. Add `--yes` only in a controlled,
non-interactive workflow. If some local records cannot be read, the command
stops by default; `--preserve-unreadable-history` keeps those records instead
of dropping them during the switch.

To rebuild the current device as a new one-device space:

```bash
uniclip space reset --yes
```

This permanently discards the old pairing, trust, and sync relationships but
keeps local history, completed files, settings, device identity, and unlock
access. Every device must pair again. This is not a factory reset.
