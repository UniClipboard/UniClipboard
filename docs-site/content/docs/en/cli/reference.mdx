This page covers the commands included in release builds and shown by
`uniclip --help`. New to the CLI? Start with [Getting started](./getting-started).
Development-only and hidden commands are documented in the repository, not in
the user guide.

## Space

| Command                     | Effect                                                                                                         |
| --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `uniclip space status`      | Show the current space and device-trust summary.                                                               |
| `uniclip space init`        | Create a new encrypted space for this profile.                                                                 |
| `uniclip space invite`      | Issue a one-time pairing invitation.                                                                           |
| `uniclip space join`        | Enter an invitation interactively, or pass `--code <CODE>`; add `--switch` to move to a different space.      |
| `uniclip space reset --yes` | Rebuild as a new one-device space while retaining local history, completed files, settings, and device access. |

Space reset permanently discards old pairing, trust, and sync relationships.
Every device must pair again. It does not erase local history and is not a
factory reset.

For scripts, `uniclip --json space init --passphrase <PASSPHRASE>` returns one
JSON object containing `space_id`, `device_id`, and `fingerprint`. The
passphrase is required because JSON mode never opens an interactive prompt.
`uniclip --json space invite` streams newline-delimited JSON: the first event
contains the invitation code and expiry, and a later event reports completion,
failure, or interruption. This lets a caller read the invitation before the
command finishes waiting for the other device.

`space join` waits for the final result by default. `--no-wait` returns after
the request is accepted; `space join status` and `space join cancel` inspect or
cancel that pending request. A space switch asks for confirmation unless
`--yes` is supplied. During a switch, `--preserve-unreadable-history` keeps
local records that cannot be read instead of dropping them.

### Join requests

| Command                         | Effect                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `uniclip space join --no-wait`  | Record a pending join and return without waiting for its final result.         |
| `uniclip space join status`     | Show the current join request and its Engine-owned status.                     |
| `uniclip space join cancel`     | Request cancellation of the current pending join.                             |

Ctrl-C stops only the local wait; use `space join cancel` when the request
itself should be cancelled.

## Members

| Command                       | What it shows                                                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `uniclip member list`         | This space's members — the local device plus paired peers — with each peer's last-known reachability: `{name} ({online \| offline \| unknown})`. |
| `uniclip member list --probe` | Same, but actively pings every paired peer first so the states are fresh (adds a network round-trip).                                            |

The former `uniclip members` command and its `uniclip devices` alias are hidden
and deprecated. They still run for compatibility, but print a warning. New
scripts should use `uniclip member list`. All three forms honour `--json`.

### Remove a member

```bash
uniclip member remove <PEER-ID>
```

Removal records an irreversible intent even when that device is offline and
immediately stops new content from being sent to it. Use
`uniclip member trust status` to inspect the current relationship state after
the removal.

### Device trust changes

| Command                                       | Effect                                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `uniclip member trust status`                 | Show the current device-group change, its identifier, and the effect of each choice.      |
| `uniclip member trust choose` | Select an available option for a current device-group issue. |

Interactive terminals can follow the prompts. Scripts and JSON callers should pass
`--issue <ISSUE-ID>` and `--choice <CHOICE-ID>` using identifiers returned by
`member trust status`. Removing this device also requires `--confirm-local-removal`.
Query again if state has changed; a submitted choice may still be pending or require re-pairing.

### Per-member sync

| Command                                        | Effect                                                                  |
| ---------------------------------------------- | ----------------------------------------------------------------------- |
| `uniclip member sync show <DEVICE>`            | Show send, receive, and content-type preferences for one member.        |
| `uniclip member sync set <DEVICE> [OPTIONS]`   | Change only the preferences explicitly supplied on the command line.    |

`<DEVICE>` can be a device ID, or an unambiguous device name in an interactive
terminal. `set` accepts `--send on|off`, `--receive on|off`, and comma-separated
`--send-types` / `--receive-types` values; use `all` or `none` for every type or
no types.

## Sending and watching

```bash
# Send text to every online paired device
uniclip send "hello from the CLI"

# Or pipe stdin
echo "from a heredoc" | uniclip send

# Restrict fan-out to specific devices (repeatable)
uniclip send "scoped message" --peer DEVICE_ID_A --peer DEVICE_ID_B

# Re-fan-out a previously captured local entry. No stdin / positional
# text is read. Without `--peer`, targets default to the diff of
# trusted peers minus those that already received this entry.
uniclip send --resend <ENTRY_ID>

# Watch inbound clipboard payloads as they arrive (Ctrl-C to stop)
uniclip watch
```

`--resend` only re-fans-out entries that were **captured locally** and
whose payload is still cached. Entries originating on a remote peer
cannot be re-sent from this device; combine `--resend` with `--peer ...`
to force a specific fan-out target.

`uniclip watch` is a **diagnostic observer**: it prints the first text
representation (or a per-rep summary for image-only payloads) but
does **not** write the system clipboard — that's the daemon's job.

### Sending and receiving files

```bash
# Sender: keep serving the file until peers fetch it. Ctrl-C stops serving.
uniclip send -f ./big-file.bin

# Receiver: wait for the first inbound file, export it from the
# daemon's cache, and write it to disk (defaults to cwd; pass --out
# for a different directory). Ctrl-C to stop waiting.
uniclip recv --out ./inbox
```

`send -f` is mutually exclusive with positional text and `--resend`. The
process stays alive after dispatch because peers fetch the bytes from it.
Keep the terminal open until the intended receivers have finished, then press
Ctrl-C. When `recv` succeeds, stdout contains only the received file's absolute
path; progress remains interactive, and `--json` returns the full result object.

### Reading already-synced entries

`recv` waits for the _next_ inbound file. To read what is **already** in
the daemon's history — the common case on a headless / SSH box with no
system clipboard to paste from — use `get`, which returns immediately.

```bash
# Newest usable entry (text/link prints to stdout)
uniclip get

# Also copy the result to the computer where this terminal is open
uniclip get -c

# Newest entry of a kind: image | file | text | link
uniclip get --type image

# A specific entry by id (from `uniclip search`), into a directory
uniclip get --id <ENTRY_ID> --out ./inbox

# Browse recent entries instead of materializing one
uniclip get --list -n 20
```

Output contract: **text / link** content is printed to stdout
(pipe-friendly). A trailing newline is appended only when stdout is an
interactive terminal, so piped or redirected output stays byte-exact;
**image / file** bytes are written to `--out` (a
directory, defaulting to a per-user cache dir) and the absolute path is
printed to stdout, or streamed to stdout with `--out -`. A successful fetch
prints no additional status lines, so the result can be piped or captured
directly. Unlike `recv`, `get` never blocks.

With `-c` or `--copy`, text and links copy their content; images and files copy
the absolute path written to disk. For images and files, `--copy` cannot be
combined with `--out -`, because streaming the bytes does not produce a path.

## Search

`uniclip search` exposes the encrypted full-text index that backs the
GUI dashboard search.

```bash
uniclip search status                    # is the index ready / building?
uniclip search rebuild                   # rebuild from history (synchronous)
uniclip search "report"                  # default query
uniclip search "report" \
    --type text --ext md \
    --limit 20 --detailed
uniclip search "report" \
    --from-ms 1710000000000 --to-ms 1710100000000
uniclip search "report" \
    --source-device "Laptop"             # only clips from that device
uniclip search "report" \
    --operator or --time-preset last_7d \
    --tag favorited --offset 20
```

Filters can be combined. `--type`, `--tag`, `--ext`, and `--source-device` are
repeatable. `--operator` selects `and` or `or`; `--time-preset` accepts
`today`, `yesterday`, `last_7d`, or `last_30d`; `--offset` and `--limit`
support pagination. A source device can be a case-insensitive name or an ID;
run `uniclip member list` to see available names. `--detailed` and `--json`
include each result's source device ID.

`rebuild` blocks until the rebuild finishes; useful when scripting a
diagnostic snapshot.

## Mobile sync

`uniclip mobile ...` is the CLI surface for the mobile companion
feature. It mirrors the **Devices → Mobile sync** panel in the GUI and
the protocol is documented in the [Mobile LAN API](../reference/mobile-api).

```bash
# One-shot wizard: turn the feature on, configure the LAN listener,
# register one iPhone, print the install QR + a one-time password.
uniclip mobile setup

# Read-only view (allowed while the daemon is running)
uniclip mobile status            # combined: feature + LAN + paired devices

# Paired device management
uniclip mobile add --label "My iPhone" \
    [--username my_user] [--password-stdin]
uniclip mobile revoke <device-id>

# Advanced listener configuration. `setup` already covers the common case;
# use these to change the address or add a reverse proxy.
uniclip mobile network interfaces
# LAN form: advertise an internal IPv4 → install URL is http://<IP>:<port>
uniclip mobile network set --ip <LAN_IPV4> [--port 42720] --accept-network-risk
# Reverse-proxy form: advertise a full base URL → install URL/QR points at
# the HTTPS front-end (e.g. Caddy), while the listener stays plain HTTP.
uniclip mobile network set --url https://clip.example.com --accept-network-risk
uniclip mobile network off       # stop just the LAN listener

# Disable the feature entirely (master switch + listener off; paired
# device records stay until you `revoke` them).
uniclip mobile disable
```

Behavioural notes:

- **Public mobile commands use the daemon.** They connect to the running
  service or start it when needed, so you do not need to stop the desktop app
  before running `setup`, `add`, or `network set`.
- **`--json` implies non-interactive.** No prompts will be shown.
  `setup` in non-interactive / JSON mode requires `--label` and
  `--accept-network-risk`. `--ip` / `--port` are optional advanced pins
  (omit them and the QR carries every detected interface). `--username` /
  `--password-stdin` remain optional and default to auto-mint.
- **`--password-stdin`** reads exactly one line from stdin. Use it to
  pipe a password from a manager / CI without leaving it in shell
  history.
- **Default port is `42720`** (SPEC §3.2). The daemon socket always
  binds to `0.0.0.0:<port>`; `--ip` only chooses the IPv4 that
  is printed to the install URL.
- **`network set` requires exactly one of `--ip <IP>` or
  `--url <URL>`.** `--ip` produces the LAN form
  `http://<IP>:<port>`. `--url` embeds a full base URL
  (scheme + host + optional port) such as `https://clip.example.com`,
  so the install URL / QR points at a TLS reverse proxy (Caddy, nginx,
  …) while the listener itself stays plain HTTP on the internal
  network. The two are mutually exclusive and setting one clears the
  other; `mobile status` reflects whichever is active.

For a step-by-step setup walkthrough — listener risks, iOS Shortcut
install, password rotation — see the [Mobile sync guide](../core-features/mobile-sync).

## Debug & log export

```bash
uniclip debug status                       # is persistent debug logging on?
uniclip debug on                           # enable verbose local logging
uniclip debug off                          # back to the normal profile
uniclip debug capture status               # inspect a connection capture
uniclip debug capture start                # start a bounded detailed capture
uniclip debug capture stop                 # stop the active capture
uniclip debug export-logs                  # zip the last 24h to Downloads
uniclip debug export-logs --since-hours 6  # narrow the window
```

`debug on` / `off` persists a more verbose logging profile across
restarts; `status` reports the effective profile and whether a restart
is still required for the change to fully take effect. Clipboard content
is still not logged.

`export-logs` collects the GUI, daemon, and CLI logs from the recent
window (default 24h) into a single zip in your Downloads folder — the
fastest way to gather everything an issue report needs. The same action
is available in the GUI under **Settings → General**.

Connection capture is intended for a short troubleshooting window. Check the
active capture with `debug capture status`, stop it when reproduction is
complete, then export the logs requested by support.

## Upgrade-detection cursor

```bash
uniclip upgrade            # bare command prints status
uniclip upgrade status     # same as the bare command
uniclip upgrade ack        # advance the cursor to the current build
```

Inspects or advances the upgrade-detection cursor — exposed for manual
verification of the upgrade module. Most users never need this.

## Exit codes

`uniclip` uses stable exit codes (defined in the source under
`src/exit_codes.rs`). `0` is success; non-zero values map to
distinct failure classes (configuration, network, pairing, etc.) and
are stable across releases. Scripts should branch on exit code rather
than parse human-readable output.

`uniclip get` additionally uses `6` when no entry matched the selector,
and `7` when an entry matched but its payload is unavailable (`Lost` or
not yet downloaded — re-send it from the source device).

For the most up-to-date list of subcommands, run `uniclip --help` —
the binary's help is the source of truth.
