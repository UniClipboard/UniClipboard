---
title: Troubleshooting
description: Causes and fixes for common errors.
---

When troubleshooting, start by running `unic status` and `unic config` to inspect the current state; when reporting an issue, attach the log bundle generated by `unic dev logs export` (see [Diagnostics and Logs](../reference/diagnostics)).

## Command reports migration_required (exit code 6)

The current data directory has not completed migration initialization.

- If you have v1 data: run `unic migrate --dry-run --json` to preflight, then run `unic migrate --json`.
- If you do not have v1 data: run `unic migrate --initialize-empty --json`.

Dry runs, partial completions, or failures do not unlock the directory; see [v1 Migration](../migration/v1-to-v2#results-and-retries).

## Configuration changes did not take effect

1. Run `unic config` and check for an `ERROR` at the top. When an error is present, the entire update is ignored and the previous valid configuration remains active.
2. Common causes: unknown keys, typos, `inbox` not being an absolute path, or values out of range.
3. `restart unicd to apply` in the output lists keys that require a restart, such as `inbox`, `history.max_bytes`, plugin lists, and plugin settings.

## Content is not syncing to other devices

- Confirm both devices appear in `unic status` and are connected.
- Check `sync.enabled`, `sync.automatic`, and `sync.files`.
- Check the built-in sync type switches under `[plugins.instances."builtin.tailcat".sync]`.
- Check whether the file exceeds `limits.max_file_bytes` (default 100 MB) or `auto_file_max_bytes`; when exceeded, auto-sync skips the entire copy, though manual send still works.
- Folders are not auto-synced by default; send them manually.
- If using plugins, check whether any has `on_error = "block_sync"`.

## A new device never appears

Devices added via pairing code must be approved locally before joining. Run `unic device list` to view pending requests and `unic device approve` to approve them. Pairing requires access to the pairing code service (`rendezvous_url`).

## Received files are rejected

When the default receive directory reaches `file_cache.max_bytes` (default 500 MB) and cleanup cannot free enough space, new files are rejected. You can:

- Increase `file_cache.max_bytes`;
- Delete unneeded history entries;
- Check whether `history.excluded_tags` is protecting too many entries;
- Switch to a custom `inbox` (where files are managed by you).

## Files in history cannot be opened

Files copied from disk are recorded by path only. If the original file is moved or deleted, the history entry can no longer be read.

## Cannot connect to the service when using UNIC_HOME

Unix socket paths that are too long (around 104 bytes on macOS) cause connection failures. Shorten `UNIC_HOME` or set `UNIC_SOCK` to a shorter path; see [Environment Variables](../reference/environment).

## Search reports unavailable

When part of the history has not been indexed yet, text and extension search report unavailable rather than returning incomplete results. Browsing by type, tag, or time still works. See [Search Syntax](../reference/search-syntax#limits).

## Migration reports partial

Some items were already missing or corrupted in v1, or v1 cleaned up files while still running. Quit v1 and rerun the same command; already imported items will not be duplicated.
