## 设备信任

- **设备身份**：每台设备首次启动时生成 Ed25519 身份密钥，保存在数据目录 `identity/device.key`（仅本人可读）。私钥不会离开本机，同步插件也无法用它签名任意数据。密钥丢失或损坏时服务拒绝启动，不会静默重新生成。
- **双向批准**：配对码和票据只证明“持有本次票据”，不授予信任。只有你核对指纹并批准，且对方也批准后，两台设备才会同步。详见[设备与配对](./devices)。
- **身份由 Engine 验证**：握手中的身份证明在 unic 核心内完成，绑定本次连接并防重放；同步后端声称“已验证”不会被采信。
- **随时撤销**：移除设备会立即撤销全部路径并中断现有会话，被移除的设备必须重新批准。

## 秘密信息的处理

设备地址、配对码、配对票据和临时传输链接都被视为秘密：

- 不写入日志、事件或错误信息（错误只以稳定的错误码呈现）；
- 不出现在设备列表与服务状态中，只能通过显式导出（`unic device addr` 或 GUI「生成票据」）获得；
- 一次性使用，最长 5 分钟有效。

快捷面板涉及的目标应用名称、窗口标识和剪贴板指纹只保存在内存中。

## 本机历史

剪贴板历史保存在本机数据库中，由你决定保留多久，可配置自动清理，见[历史与搜索](./history-and-search)。标签和过期设置不会同步到其他设备。

## 遥测与诊断

unic 默认开启四类诊断上传：日志、指标、采样链路追踪（根链路固定 1% 采样）和产品使用事件。

- 上传内容经过白名单过滤，**不包含剪贴板内容**、设备地址或票据，只保留服务名称/版本、操作系统类型和架构等资源信息。
- 产品统计使用一个独立的随机标识，与设备身份无关；关闭后再开启会更换该标识。不做个人画像与 GeoIP 处理。
- 上传失败不重试，也不会阻塞剪贴板同步。

在 `config.toml` 中关闭（保存即生效）：

```toml
[telemetry]
enabled = false        # 关闭全部上传

# 或只关闭某一类
[telemetry.logs]
enabled = false
[telemetry.metrics]
enabled = false
[telemetry.analytics]
enabled = false
[telemetry.traces]
enabled = false
```

修改 `telemetry.endpoint` 需要重启服务。环境变量不能开启上传或改变上传目标。

本地日志与上传独立：以 JSON Lines 写入数据目录，单文件 4 MiB、总量不超过 20 MiB、保留 7 天。本地级别由 `[logging] level` 控制（默认 `info`）。如何导出日志与临时调高级别见[诊断](../reference/diagnostics)。

## 发布包校验

当前 v2 本地打包生成的压缩包附带 SHA-256 清单，但**尚未签名**：校验和只能证明文件完整，不能证明发布者身份。不要把 v1 的更新签名密钥用于 v2。

## 报告安全问题

请通过 GitHub 的[私密漏洞报告](https://github.com/UniClipboard/UniClipboard/security/advisories/new)提交，不要在公开 issue 中披露未修复的漏洞。请注明分支与具体提交或版本、复现步骤、受影响平台和影响，并移除附件中的剪贴板内容、凭据、设备地址和配对票据。
