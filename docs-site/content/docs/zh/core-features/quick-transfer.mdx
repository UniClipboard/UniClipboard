---
title: 临时传输
description: 无需配对，用 6 位传输码或链接把一段内容一次性发给另一台设备或网页。
---

临时传输用于和**没有配对**的对象交换一次内容，例如别人的电脑，或浏览器里的 `try.uniclipboard.app` 页面。它不会创建设备、也不会建立任何信任关系。

<Callout>
临时传输目前只在命令行提供，桌面端没有入口。
</Callout>

## 发送

不带 `--to` 运行 `unic send` 即开始临时传输：

```bash
unic send "hello"
unic send -f ./photo.jpg
echo hello | unic send
```

命令会打印一个 6 位**传输码**和一个**链接**，然后等待一个接收方：

```text
Code: 482 913
Link: https://...
On the other device run: unic recv <code or link>
```

- 传输码最长 5 分钟有效，只服务一个接收方。若传输码服务不可用，只会打印链接，链接同样可用。
- 按 `Ctrl+C` 取消，此时不会交付任何内容。
- 加 `--json` 时第一行输出包含链接和传输码。

## 接收

在另一台装有 unic 的设备上：

```bash
unic recv 482913          # 空格和短横线可省略
unic recv 'https://...'   # 也可以粘贴链接
```

文本会直接打印出来，文件写入本机收件目录。收到的内容会进入本机历史（来源为"外部"），可用 `unic history list` 或 `unic recv list` 查看，但**不会自动写入系统剪贴板**。

对方也可以直接在浏览器打开链接接收。

## 限制

| 项目 | 限制 |
|---|---|
| 单次大小 | 最多 20 MiB |
| 单次条目数 | 最多 50 项 |
| 内容类型 | 文本、图片、普通文件；**不支持文件夹** |
| 方向 | 只能由 unic 发出、对方拉取；网页回传（push）不支持 |

- 传输码与配对码不能混用：`unic recv` 会拒绝配对码，`unic device add` 也会拒绝传输码。
- 接收方仍受本机同步总开关、接收策略和存储空间约束。
- "已交付"表示接收方校验了内容哈希并确认收到，不代表对方已写入历史或剪贴板。
- 传输码、链接和地址不会写入日志。

需要长期、双向同步时，请改用[设备配对](./devices)。
