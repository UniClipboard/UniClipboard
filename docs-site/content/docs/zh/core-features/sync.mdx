title: 剪贴板同步

---

unic 在已配对并互相批准的设备之间同步剪贴板。每次复制先写入**本机历史**，再按设置发送给其他设备；发送失败不会撤销本机历史。

## 一次复制经历什么

```mermaid
flowchart LR
  A["复制 / 显式发送"] --> B["处理（打标签、决定是否保存/同步）"]
  B --> C["写入本机历史"]
  C --> D["发送到已配对设备"]
  D --> E["对端写入历史并应用到剪贴板"]
```

- **处理**：内置分类器和插件只能给内容打标签、设置过期或禁止同步，**不会修改正文**。复制的是什么，同步过去的就是什么。
- **提交**：内容先保存到本机历史；即使同步关闭、没有已配对设备或网络断开，也照常保存。
- **发送**：提交成功后才发送。发送失败只记录在该历史条目的同步状态里，不会重试已中断的发送；服务重启后未完成的发送会标记为已中断。
- **接收**：对端先检查大小、类型策略和存储空间，再接收正文。收到的内容**不会被再次转发**给第三台设备。

## 支持的内容

| 类型 | 说明 |
|---|---|
| 文本 / 富文本 | 富文本即带 HTML 的文本 |
| 图片 | 以 PNG 等图片格式传输 |
| 文件 | 单个文件默认上限 100 MB（`limits.max_file_bytes`） |
| 文件夹 | 默认**不自动同步**，需显式发送，见[文件夹](#文件夹) |

## 常用开关

在桌面端设置中修改，或用 `unic config set` 写入 `config.toml`（保存即生效）：

| 配置键 | 默认值 | 作用 |
|---|---|---|
| `sync.enabled` | `true` | 总开关；关闭后只在本机记录历史 |
| `sync.automatic` | `true` | 复制后自动发送；关闭后只有显式发送才会同步 |
| `sync.files` | `true` | 是否收发文件（双向生效） |
| `sync.on_restore` | `false` | 从历史恢复某条内容时，是否再次发送给其他设备 |
| `sync.directories.automatic` | `false` | 复制文件夹时是否自动准备并发送 |
| `limits.max_file_bytes` | `100MB` | 单个文件可传输的上限；超过的文件仍可进入本机历史 |

每个同步后端还可以单独设置是否传文本、图片、文件，以及自动发送文件的大小阈值（`plugins.instances.<后端>.sync.auto_file_max_bytes`，0 表示不额外限制）。显式发送不受该自动阈值限制。完整配置项见[配置参考](../reference/configuration)。

```bash
unic config set sync.automatic false
unic config set limits.max_file_bytes '"200MB"'
```

## 显式发送

不想等自动同步，或自动同步已关闭时，可以主动发送：

```bash
echo hello | unic send --to all          # 发给所有已配对设备
unic send --to laptop "hello"            # 发给指定设备（名称或 ID）
unic send --to all -f ./report.pdf       # 发送文件
unic history send @1 --to laptop         # 重新发送历史中的最新一条
```

`unic send` 会等待本次发送结束：内容已保存但发送未完全完成时退出码为 `4`。不带 `--to` 时会改为[临时传输](./quick-transfer)。

## 文件夹

复制文件夹时，unic 默认只在本机历史中记录一个**来源引用**，不扫描内容、也不发送。需要发送时显式操作：

```bash
unic send --to all -f /absolute/path/to/folder
unic history send @1 --to laptop
```

显式发送时才会读取文件夹当前内容，生成一份不可变快照发给所有目标。要点：

- 可以混合选择文件与文件夹；保留空文件夹和隐藏文件。
- 符号链接、快捷方式（junction）和特殊文件会让整次发送失败，而不是被跳过。
- 不保留所有者、权限、时间戳和扩展属性。
- 上限：最多 128 个顶层项、4096 个条目、2048 个文件。
- 文件夹必须发给已配对设备（`--to`），[临时传输](./quick-transfer)不支持文件夹。
- 发送后源文件夹的改动不会自动同步。

打开 `sync.directories.automatic` 后，复制文件夹也会自动准备并发送；更新的复制会取消尚未完成的旧文件夹准备。

<Callout type="warn">
Linux 桌面端目前无法区分"再次复制同一个文件夹"，对相同选择请使用显式发送。各平台的原生剪贴板与跨应用粘贴尚在验收中。
</Callout>
