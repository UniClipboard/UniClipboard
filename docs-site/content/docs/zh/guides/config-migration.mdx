description: 把一台设备的剪贴历史、设置和配对关系，整体搬到另一台新装的 UniClipboard 上，搬完不用重新配对。
---

简单说：这是 **把一台设备整体「搬家」到另一台机器** 的功能。

你在 **设置 → 存储** 里把当前设备导出成一个加密文件，拿到另一台 **全新安装** 的
UniClipboard 上导入，重启之后 —— 剪贴历史、设置、以及和其它设备的配对关系都还在，
**不用重新配对**。

<Callout type="warn">
  这是「搬家」，不是「多机备份」。导入会把这台设备的 **身份** 一起搬过去：导入后
  那台新机器就 **变成了** 你原来那台设备。所以 **搬完之后不要再让原设备上线** ——
  两台带着相同身份的设备同时在线，会在设备网络里互相打架。详见
  [搬家语义](#搬家语义为什么不能两台同时在线)。
</Callout>

## 什么时候用

- **从便携版换到安装版。** 便携版（绿色版，免安装、放 U 盘里跑那种）不能应用内自更新，
  很多人想换成安装版长期用。但直接把便携版的 `data` 文件夹复制到安装版旁边是 **没用的** ——
  安装版根本不去那里读，而且密钥的存放方式两边也不一样，复制文件带不过去。这正是
  [issue #1110](https://github.com/UniClipboard/UniClipboard/issues/1110) 要解决的问题。
  用导出 / 导入就能干净地完成这次切换，包括 **不用重新配对**。
- **换电脑。** 旧电脑退役、换新机，把整套配置搬过去。
- **临时备份 / 恢复。** 留一个加密文件当快照，机器出问题时在一台新装的机器上恢复。

> 「便携版 / 安装版」「身份 / NodeId」这些词第一次出现时都会先用人话解释，看不懂可以先往下读。

## 你需要先知道的三件事

1. **目标机必须是「全新未初始化」的。** 也就是刚装好、还没创建过空间、也没加入过任何空间的状态。
   如果目标机已经在用了，要先做一次「恢复出厂设置」把它清空，再导入。见
   [目标机已经初始化过怎么办](#目标机已经初始化过怎么办)。
2. **导出时这台机器要处于已解锁状态。** 解锁就是你平时输入同步口令（passphrase）把历史解开的那一步。
   这是一道授权关卡 —— 防止有人对着一台锁着的机器，把里面的身份和数据偷偷导走。
3. **导出和导入用的口令，建议直接用你的同步口令。** 导出时会让你设一个口令给这个文件加密，
   导入时要输入同一个口令。直接复用你已有的同步口令最省事，这样你只要记住一个秘密。
   当然你也可以另设一个专门的口令。

## 导出（在要搬走的那台设备上）

1. 打开 **设置 → 存储**，找到 **「配置备份 / 迁移」** 分组，点 **「导出配置」**。
2. 输入一个口令给导出的文件加密 —— 建议直接用你的同步口令。
3. 选一个保存位置。
4. 得到一个加密的 `.ucbundle` 文件。它里面打包了：剪贴板历史、设置、设备身份、密钥材料 ——
   **全部用你刚才输入的口令加密**，没有口令谁也打不开。

<Callout type="info">
  导出需要当前已解锁。如果还在锁屏页，先输入同步口令解锁，再来导出。
</Callout>

把这个 `.ucbundle` 文件传到目标机上（U 盘、网盘、局域网传文件都行）。文件本身是加密的，
传输过程不怕被看到，但口令请通过其它渠道告诉自己 / 不要和文件放一起。

## 导入（在那台全新设备上）

前提：目标机是 **全新、未初始化** 的（见上文第 1 点）。

1. 在目标机上打开 **设置 → 存储 → 配置备份 / 迁移**，点 **「导入配置」**。
2. 选刚才那个 `.ucbundle` 文件。
3. 输入 **同一个口令**（你导出时设的那个）。
4. 屏幕上会显示这个文件的 **来源信息**（版本、来源类型、设备指纹）让你 **再确认一次**。
   核对没问题后点确认。
5. 应用会应用配置并 **自动重启**。重启之后，历史、设置、配对关系都在了 —— **不用重新配对**。

<Callout type="info">
  如果导入后界面提示需要解锁，输入你的 **同步口令** 即可。这是正常的：当导出文件用的是
  你自定义的另一个口令、而不是同步口令时，导入后系统还需要你的同步口令来解开历史。
  用同步口令导出的话，一般不会再问你。
</Callout>

## 搬家语义：为什么不能两台同时在线

UniClipboard 用一个稳定的 **设备身份**（技术上叫 **NodeId**，是一把固定的公钥）来认人。
设备之间的配对关系、信任、谁能收谁的内容，都绑在这个身份上。切 Wi-Fi、重启、换 IP 都不影响它。

导出 / 导入 **会把这个身份一起搬过去**。所以这不是「复制一份」，而是「搬家」：

- 导入后，目标机 **就是** 你原来那台设备 —— 在其它设备眼里它们是同一台，所以才不用重新配对。
- 正因为身份只有一份、却被搬到了两台机器上，**原设备和新设备不能同时在线**。两台带着
  相同 NodeId 的设备同时连上设备网络，会互相冲突、行为不可预期。

<Callout type="warn">
  **搬完家，就让原设备退役。** 确认新机器一切正常后，不要再启动原设备上的 UniClipboard
  （或者把它重置 / 卸载掉）。如果你真正想要的是「两台机器各自独立、都能用」，那应该走
  正常的 [配对流程](./pairing) 再加一台设备，而不是用导入。
</Callout>

## 常见问题

### 目标机已经初始化过怎么办？

导入要求目标机是 **未初始化** 状态。如果它已经创建 / 加入过空间，导入会被拒绝。
先在目标机上做一次 **恢复出厂设置**（会清掉它本机现有的历史和密钥），把它退回到未初始化状态，
再来导入。恢复出厂设置的入口和影响见
[故障排查 — 紧急重置](../help/troubleshooting#紧急重置最后手段)。

<Callout type="warn">
  恢复出厂设置会 **清空目标机本机现有的剪贴历史**，不可回滚。只在确认那台机器上没有要留的
  数据时再做。
</Callout>

### 导入后提示需要解锁？

输入你的 **同步口令** 解锁即可，历史会照常出现。详见上文
[导入](#导入在那台全新设备上) 末尾的说明。

### 口令输错了会怎样？

文件打不开，提示口令错误或文件损坏（两者不区分，避免泄露线索）。重新输入正确口令即可，
你的数据不会有任何损坏。

### 这会动到原设备上的数据吗？

不会。导出只是 **读取并打包**，原设备上的历史、设置、配对都原封不动。真正需要注意的是
搬家之后 **别再让原设备上线**（见 [搬家语义](#搬家语义为什么不能两台同时在线)）。

### 和「重新配对一台新设备」有什么区别？

- **导入 = 搬家。** 把同一台设备搬到新机器，保留身份和历史，原设备退役。
- **配对 = 加一台新设备。** 两台机器各有独立身份，都在线、各自独立工作，新设备从加入那刻起
  才开始同步、不会拿到旧历史。需要这种效果就走 [配对流程](./pairing)。
