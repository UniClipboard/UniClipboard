# ADR-011：桌面端接入 Engine 成员收敛状态

- **状态**：已实施
- **日期**：2026-08-11
- **上游**：UniClipboard/Engine PR #24，固定提交 `983fb2562f55fca3838a927f7831ae51eaadf885`

## 背景

成员加入、移除和离线设备等待曾分别通过短期设备发现和独立移除状态呈现。两套状态无法
说明同一个成员变更是否已经由全部有效设备应用，产品端也会把“离线”误解成“当前必须上线”。

Engine PR #24 将它们收敛为一份持久的 Workspace convergence 状态。该状态由 Engine 唯一
拥有，桌面端只负责传递和展示。

## 决策

1. 桌面端固定使用 PR #24 当前提交，并完整透传 Workspace convergence 状态。
2. HTTP 返回与实时通知均使用同一份状态；收到实时通知后重新读取当前状态，避免客户端
   自行合并快照。
3. 设备列表只根据 `waiting_member_device_ids` 标记需要上线的指定设备；普通离线设备不显示
   资料更新警告。页面顶部不再显示统一的等待提示。
4. `removed` 是本机已被移除的独立长期事实；它不等同于收敛阶段，只有重新加入 Space 后
   才会清除。
5. 用户取消配对仍通过既有入口发起。Engine 负责持久化、传播、恢复与完成判定；桌面端不
   维护第二套移除或重试逻辑。

## 状态含义

| 阶段 | 产品含义 |
| --- | --- |
| `locally_applied` | 本机已经应用成员变更，正在等待进一步传播。 |
| `converging` | 有效成员正在应用同一成员状态。 |
| `waiting_for_offline_member` | Engine 指定的一个或多个有效成员需上线才能完成。 |
| `complete` | 全部有效成员已完成当前成员变更。 |
| `recovery_required` | 无法继续收敛，需要通过可信设备恢复 Space。 |

## 验收

- Engine 指定某设备等待上线时，只有该设备条目显示资料更新警告。
- 指定设备上线并完成更新后，警告随 Engine 状态消失。
- 本机被移除时，设备页明确显示已被移除；重新加入后状态恢复。
- 自动成员发现、移除和重启恢复均以 Engine 返回的当前状态为准。

## 不做的事

- 不从设备在线状态推断等待名单。
- 不保留独立的设备发现或成员移除状态接口。
- 不在桌面端实现成员收敛的重试、完成判定或状态合并。
