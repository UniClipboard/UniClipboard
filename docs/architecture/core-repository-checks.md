# 核心仓库迁移检查

在物理拆仓前，desktop 仓通过一个统一入口执行核心仓库迁移检查：

```bash
bun run check:core-repository
```

该入口读取 Cargo 提供的结构化依赖信息，并检查以下规则：

- 待迁移核心不能依赖 desktop 拥有的 crate 或仓库内其他路径。
- 核心内部 crate 禁止单独发布；外部 Rust 使用方只通过 `uc-engine`。
- desktop 保留 crate 禁止直接依赖核心内部 crate 或 LAN 协议 crate。
- UniFFI 与 HarmonyOS 绑定必须和 `uc-engine` 使用同一版本，打包脚本必须记录版本、来源提交和校验值。
- 明文扫描器必须接受干净目录并拒绝含探针明文的目录，同时不得输出探针内容。
- LAN 兼容能力默认关闭，只能由明确的兼容构建和用户设置启用；P2P 失败不能触发 LAN。

检查程序自带三个隔离的错误样例，分别模拟反向路径依赖、绑定版本不一致和自动 LAN 回退。每次执行都必须证明三个样例会被拒绝。

## 拆仓后的归属

- 核心依赖、公开入口、绑定来源和密文持久化检查迁入 `UniClipboardCore`。
- desktop 消费者检查和 LAN 显式启用检查留在 desktop 仓。
- 两边都只读取固定版本或提交，不允许依赖分支、浮动标签或本地路径。

现有 crate 级检查继续用于定位局部回归；本入口负责判断整个迁移集合是否满足拆仓条件。
