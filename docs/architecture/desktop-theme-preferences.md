# desktop 本地主题偏好

Omarchy 主题开关由 desktop 的 `uc-tauri::desktop_theme` 模块持有。它不属于 Engine，不进入 daemon 设置接口，也不参与设备间同步。

## 存储与所有权

当前配置档案的数据目录由 `uc_app_paths::app_data_root()` 解析，偏好文件为 `desktop-preferences.json`：

```json
{
  "followOmarchyTheme": true
}
```

文件或字段缺失时默认开启；已明确保存为关闭的选择保持不变。保存通过同目录临时文件、文件同步和原子替换完成。Rust 层串行执行保存，成功后才更新内存快照并广播 `desktop-theme://changed`；失败时保持原状态，并向发起操作的控件返回错误。

该布尔值只表示是否采用本机 Omarchy 配色，不包含剪贴板内容、路径、设备身份或调色板。此实现采用明文偏好，便于在 Engine 未启动或未解锁时决定窗口外观。根据根目录 `AGENTS.md` 的持久化规则，PR 必须明确列出并审批这一非敏感配置例外；不能将本文件的格式作为添加其他明文业务数据的依据。

## 应用规则

- 开启且调色板可用：由 Omarchy 控制深浅模式及完整配色，禁用手动主题控件。
- 关闭：应用原有主题设置；原设置始终保留，不保存平行备份。
- 开启但启动时无法提供调色板：保留偏好，临时使用应用主题，并允许用户关闭开关。
- 运行中调色板替换或读取失败：保留最后有效配色，沿用现有监听器的恢复行为。
- 不支持 Omarchy 且未开启时：隐藏专用开关。

主窗口与快捷面板使用同一主题控制器。原有系统深浅模式跟随、合成器圆角与动效设置保持各自职责；关闭 Omarchy 配色不会关闭圆角适配。

初始快照在加载本地偏好后提供。事件与命令响应携带递增版本，前端忽略过期结果；隐藏窗口恢复可见时重新查询快照。
