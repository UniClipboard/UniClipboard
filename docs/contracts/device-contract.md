# 统一设备、身份与同步后端关联契约

- 状态：已实现并有测试：统一设备身份与信任、按后端实例的关联授权、候选/配对、设备介绍、撤销；密码学协议见[身份协议](identity-protocol.md)。对象存储路径与 macOS 界面未做。
- 日期：2026-11-08。
- 依据：[身份与信任](../architecture/identity-and-trust.md)、[0007](../decisions/proposed/0007-multiple-sync-backends.md)、[Engine 契约](engine-contract.md)、[同步后端契约](sync-backend-contract.md)。
- 范围：全新设计，无旧身份、地址、配对记录、票据、SDK 或设备协议的兼容要求。本文在设备身份、关联和审批方面优先于既有 P2P 草案；不据此更改本机插件 RPC 帧格式。

## 1. 概念与所有权

| 实体 | 含义与所有权 |
|---|---|
| Device | Engine 中的稳定设备记录：DeviceID、身份公钥绑定、名称、信任状态与修订；ID 不透明，不能单独作为认证证据 |
| Plugin implementation | 插件程序/实现身份，与安装版本、声明能力关联 |
| Backend instance | 一个具体配置的同步后端实例；稳定实例 ID、实现引用、配置和标准策略；同一实现可有多个实例 |
| DeviceBackendBinding | Engine 管理的设备与本地后端实例之间的关联；含稳定关联 ID、远端身份/上下文绑定、授权状态与修订、同步开关和状态摘要 |
| Discovery candidate | 后端发现但尚未归并/授权的候选：来源实例、后端内候选引用、身份验证状态、发现时间和到期；自报名不可信 |
| Pairing attempt | Engine 创建的有期限操作，绑定候选/目标、实例、上下文、身份材料与审批修订；完成/取消后不再授予新权限 |
| RPC binding_id | 每次 Engine 与插件进程绑定产生的临时随机 token；不是设备关联 ID，也不是配置实例 ID |

同一设备在一个实例中可有多个地址或端点，它们属于该关联的内部定位信息，不因地址数增加设备行。多个独立仓库使用多个配置实例。DeviceBackendBinding 不保存另一套设备信任；有效权限取设备信任与关联授权的交集。

Engine 保存全局身份与授权；插件私有目录保存该实例的网络密钥、仓库凭据、游标等后端数据。Engine 身份私钥不传给插件。可信本机 Go 插件仍不是恶意程序沙箱；短期 RPC 授权防止句柄混用，不承诺隔离同用户权限的恶意进程。

## 2. 统一身份与证明

Engine 在本机初始化阶段生成并持久化设备身份，跨重启保持。插件独立生成自己的传输身份；tailcat 密钥不等于设备身份。已有身份文件损坏、无法读取或密钥不符时，停止相关操作并报告稳定错误，不能悄悄生成新身份替代。密钥重置、轮换、备份克隆和账号恢复须另定规则；本契约不提供隐式恢复。

远端提交 DeviceID 和身份公钥时，Engine 验证协议规定的持钥证明及已登记绑定；同一 ID 配不同公钥属于身份冲突，不覆盖记录。名称和地址不能作为身份归并依据。不同 ID 的记录也不得仅凭插件判断自动合并。

P2P 证明须绑定双端身份、双方的新鲜挑战、本次协议和会话上下文；对象存储须验证来源设备身份、仓库上下文及协议规定的防重放信息。普通共享凭据只证明能访问仓库，不能证明某台设备身份。后端仅负责传送证明；Engine 不接受任意 `verified=true` 作为认证结果。

首次配对需要展示绑定身份及配对上下文的核对信息；不能沿用两个自报 ID 的哈希充当密码学身份认证。指纹算法、握手编码、签名域、挑战/重放窗口、连接绑定、防降级及对象存储内容保护必须在实现前形成版本化协议与正反向向量，采用标准密码学原语及库；本文没有指定一个可直接实现的完整密码协议。

统一设备级信任本身不授予新后端路径权限。所有发送、接收和签名操作都必须检查当前关联、用途和代次；不向插件开放任意载荷签名接口。具体最小 RPC 在后续 Schema 中定义。

## 3. 发现、配对与关联授权

1. 插件报告候选及来源。Engine 限制候选资源并在到期后移除临时候选；未验证候选不按自报 DeviceID 合并到可信设备，不能污染已有名称或状态。
2. 用户选择目标和接入实例，Engine 创建配对操作。配对码由 Engine 管理，票据需包含版本、传输种类、远端接入描述及一次性材料；远端实例 ID 不要求与本地相同，必须由本地选择兼容实例，不能凭票据安装/启动未知程序或取得本机授权。
3. 插件执行连接或仓库消息交换，Engine 验证统一身份与配对上下文。无兼容后端或无所需能力时返回明确不可用结果，不偷偷使用 tailcat 兜底。
4. 新设备核对身份并审批；用户主动确认的操作可以授权本机所选设备及路径。通过配对码进入的一方始终需要出码方用户批准；票据只负责发现和关联本次尝试，不授信。
5. 已验证的已有设备添加新路径时，复用设备身份记录，但新关联仍默认等待用户确认。无需重复建立同一设备身份，不自动启用所有发现的路径；双方各自授权，不以一侧确认推定另一侧已批准。
6. 桌面聚合审批使用 `Engine.ApproveDevice`，请求包含设备 ID/修订、必须核对的指纹与完整待批准关联 ID/修订；SQLite 单事务检查设备和全部待批准关联后一起授信及授权，缺少/新增/改变关联或任何写入失败都不部分生效。已信任设备新增关联同样核对指纹。`TrustDevice` 与 `AuthorizeBinding` 仍可供宿主分别审批设备与单条路径。审批须绑定请求修订、期望身份核对值、实例、关联和远端上下文；任一变化使旧审批失效。取消、超时、拒绝、进程重启或操作完成后的迟到材料不能授予新关联权限。
7. Engine 持久化本机批准后推进状态，再向插件发布授权；P2P 双方都接受才形成内容会话。对象存储按其成员与内容协议判断，不伪造双向在线状态或远端应用确认。

发现入口不是每个插件必备能力。插件可以提供主动发现、显式地址接入或仓库成员发现等能力，Engine 按实际声明提供 UI；所有能传输设备内容的后端必须提供可验证来源和执行授权/撤销的能力。

票据的失效、消费、TTL、限速与强制批准原则保留配对码的既有约束；新票据编码、身份核对算法和设备握手替换其旧格式。首次只交付 tailcat，不强迫对象存储实现 P2P 的 PairingAddress/Dial/connected。

## 4. 状态、列表与宿主展示

设备列表以 Device 为一行，展开各关联的实例名称、插件实现、关联授权、同步开关、后端可用性、可达性、最近活动、最近成功同步和稳定错误。待批准请求单独标识，不能显示为可同步的已信任设备。

发现来源与已授权关联分别展示。一条路径失败不能把其他路径成功覆盖，也不能把设备聚合“可同步”解释成全部路径正常。P2P 可以报告已连接/断开；对象存储报告仓库可用、成员已验证、轮询/同步时间，不用仓库在线推导设备在线。后端未提供的信息标为未知，不猜测。

外部渠道（[0009](../decisions/proposed/0009-external-channels.md)）不是设备，不写设备表，没有指纹与核对步骤；它与设备混排在用户可见的对端列表中，列表项带种类（SDK `Peer.Kind` 为 `device` / `channel`；桌面 HTTP 的 `PeerStatus.kind` 为空 / `external`）。渠道的有效权限只取决于“已启用”，不适用“设备级信任 ∧ 关联授权”。移除渠道只在本地生效，除非后端声明 `remote_revocation`；声明时先停用并请求退出远端组，成功才清除本地记录，失败则保留并标记 `remove_failed`。

设备级名称与插件发现的自报名分开存储；未经用户操作的发现不得覆盖用户设置的名称。普通列表、State/Event 不包含秘密地址、票据、凭据、身份私钥、RPC token 或绝对路径。查看地址必须走显式受控接口。

SDK 应提供统一设备查询与关联查询、候选/待批准查询、添加/批准/拒绝、关联启停/移除和解除设备配对；操作遵守请求幂等与 CAS 修订，具体类型随 SDK 契约补齐。状态变化需要主动发布事件，宿主不得只凭本地计时猜测权威状态。

## 5. 权限与撤销

内容传输至少同时满足：Engine 运行状态允许、全局同步启用、实例启用且可用、设备身份已验证且信任有效、关联授权有效且同步启用、条目与后端策略允许、当前任务的短期授权有效。对象存储的仓库发送还须满足其成员/仓库授权协议；不能把某台设备关联授权等同于向所有仓库读者授权。

| 动作 | 语义 |
|---|---|
| 暂停某关联同步 | 立即拒绝该关联的新内容工作，取消该路径在途内容任务；保留信任、关联和必要控制消息 |
| 移除某关联 | 撤销该关联及其会话、传输授权；重新发现不自动恢复 |
| 解除设备配对 | 撤销设备信任与所有关联授权；重新加入需要新审批，发现不能复活旧信任 |
| 禁用/卸载插件 | 停止实例工作，保留设备及关联并标示不可用，不影响其他实例 |
| 同一实例修改仓库/账号上下文 | 先撤销旧上下文授权，新上下文重新验证和审批；不得沿用实例 ID 继承授权 |

撤销在 Engine 本地提交时立即禁止发放新授权，成功返回还需获得对应后端屏障；外部后端可终止不响应的进程并确认回收，builtin 后端须关闭端点并确认任务退出，不能确认则停止同步服务并报告失败。迟到响应不能重新启用旧代次。对象存储已上传数据和已持有密钥的远端副本不可能靠本地 Unpair 撤回；未来内容的成员排除、访问控制或密钥更新必须由对象协议落实，否则不能宣称该后端已完成远端成员撤销。

安装/恢复插件后重新验证身份、实例上下文与最新授权，不用插件缓存重建已撤销信任。全局同步关闭不禁止本机设备管理、必要配对或健康检查，但所有内容上传、下载、轮询和重试停止。

## 6. 实施前置与验收

先补齐统一身份/配对网络协议、实例标识与配置、SDK DTO、RPC 方法/Schema/向量及对象存储的适用约束，再接入后端。现有 P2P 业务草案中依赖自报 hello、wire v2、全量 peers/rejected 的部分必须按设备关联收敛，不能直接作为本目标的安全实现。

验收覆盖设备归并、多实例隔离、无 tailcat 配对、默认关联审批、全路径撤销与身份攻击用例，并覆盖两个后端并发发现/批准、过期审批、实例上下文切换、插件重启、对象存储离线状态和秘密脱敏。文档定义不代表上述运行测试通过。
