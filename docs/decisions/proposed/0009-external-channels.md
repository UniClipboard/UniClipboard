# 0009 · 外部渠道：没有 unic 身份证明的第三方对端

- 状态：草案；数据模型、引擎 API、接收路径与桌面 API 已实现（`engine/channels.go`、`unicd` 的 `/v1/channels`），尚无真实后端；首个对象是微信输入法（WeType）剪贴板组，接入方式（wxc 子进程或插件 RPC）另定。
- 日期：2026-11-08。
- 依据：[0007 多后端](0007-multiple-sync-backends.md)、[0008 统一设备身份](../archive/0008-device-identity-and-backend-bindings.md)、[身份协议 v1](../../contracts/identity-protocol.md) §7。
- 产品尚未发布：直接调整接口与存储，不写迁移或兼容分支。

## 背景

0008 要求每台设备持有 Engine 登记的身份密钥，路径必须证明持有该密钥。有些服务不可能满足：微信输入法的对端是官方应用，设备标识是服务端分配的 Uin，没有 unic 公钥，也不会对握手签名。它的模型是同步组：发到组里的内容，组内所有官方设备都会收到，无法只发给其中一台。

要让用户把它当作"另一个能互相同步的对端"，又不能伪造密码学身份。

## 决策

### 1. 外部渠道不是设备

新增外部渠道（external channel）记录，隶属于后端配置实例，不写入 `devices` 表，没有公钥、DeviceID 或指纹。为它造一把假密钥会让"核对指纹"失去意义，因此不做。

授权只有一个来源：用户在对方服务里完成配对（微信输入法为官方 6 位码），再在 unic 里启用该渠道。启用即本地授权；没有远端批准这一步，因为远端已在官方配对时完成。

### 2. 目标是组，不是设备

一个渠道对应一个发送目标（目标类型 `group`）。一次发送只有一条目标状态；组内成员（Uin）只作只读信息展示，不能单独授权、暂停或撤销。需要指定官方设备的文件传输留待以后增加，不在本决策内。

回执语义随后端声明：微信输入法的文本与图片回执只表示服务端已接受，不表示对端已写入剪贴板；界面使用"已送达服务端"而不是"对方已收到"。

### 3. 设备列表混排

对用户而言，外部渠道与设备同属"能互相同步的对端"，在同一个列表中展示，不另设分区，也不展示"已验证/未验证"。内部差异保留：

- 外部渠道没有指纹，没有核对步骤；
- 详情中显示所属后端与目标类型；
- 移除只在本地生效（见 §5）。

### 4. 收到的内容

渠道有"自动写入剪贴板"开关，默认开。收到的条目照常进入 received 流水线与历史，来源标为 `external:<后端实例>`，不标记为任何设备。组内成员或服务端都可能注入内容；这一风险由用户通过关闭渠道或自动写入自行控制，Engine 不据此改变去重、历史或 Action 的行为。

跨后端去重沿用 0007：同一内容经 tailcat 和外部渠道各到一次，只提交一次。

### 5. 撤销只在本地生效

停用渠道：立即停止发送和接收，丢弃进行中的任务。移除渠道：另外清除本地凭据与状态。后端必须声明 `remote_revocation = false`；微信输入法没有已知的退出组请求，因此界面与结果都不得显示"已从组中移除"，移除确认处写明"不会退出微信输入法的组，请在官方应用中移除本设备"。

已经发送的内容不能撤回。

当前 wx-ime-sdk 没有退出组的请求（只有取消尚未完成的配对），所以首版就是上述本地语义。后端一旦提供远端退出，`remote_revocation` 改为 `true`，移除流程变为：先发退出请求；确认成功才清除本地凭据并显示"已退出"；失败则保留渠道与凭据，状态置为"移除失败"并给出可重试的错误，不得在远端未退出时丢掉凭据（否则本机再也无法退出）。

### 6. 隐私与默认值

外部渠道的内容会离开 unic 的设备间链路进入第三方服务。启用时必须明确提示；按类型策略（0007）默认只开文本，图片和文件由用户另开。凭据与状态放在该后端实例的私有目录，不进日志、事件、错误或 DTO。

### 7. 对既有设计的影响

- 设备契约：对端列表项增加种类字段（SDK `device` / `channel`，桌面 HTTP 空 / `external`）；"设备级信任 ∧ 关联授权"对外部渠道简化为"渠道已启用"。
- 身份协议：不改。外部渠道不使用 §4 的证明。
- 0007：目标类型增加 `group`；`SyncTargetKind` 与 `plugin.SyncBackend` 的目标 ID 约定不变。
- 后端声明增加：配对方式（`native`：由后端自己的流程完成，不经 rendezvous 与票据）、`remote_revocation`、回执语义。

## 实现状态

- 引擎：`Channel`/`Peer` DTO 与渠道 CRUD、混排 `ListPeers`、`TargetGroup`、接收 `plugin.Receiver`、历史来源 `external`；见 [Engine 契约](../../contracts/engine-contract.md)。
- 桌面：`unicd` 的 `GET /v1/status` 混排渠道；`PATCH/DELETE /v1/channels/{id}`；`channel` 事件；`AutoApply` 关闭时不写剪贴板。命令行与 mygo 桌面界面尚未展示渠道；SwiftUI 客户端路线已取消，桌面界面原型待定。
- 进程外后端：插件 RPC 外部渠道子集已实现（见同步后端契约 §6a，真实子进程测试）。
- 未实现：真实渠道后端（微信输入法）、文件传输。

## 验收

- 外部渠道不出现在 `devices` 表，没有指纹字段；启用/停用/移除互不影响设备。
- 一次发送对该渠道只产生一条目标状态；失败不影响 tailcat 等其他后端。
- 收到的内容默认写入剪贴板并标注 `external:` 来源；关闭自动写入后只进历史。
- 移除渠道后本地不再发送也不再接收，结果与界面不声称远端已移除。
- 同一内容经两个后端到达只提交一次。
- 凭据、Uin 和服务端地址不出现在日志、事件、错误或列表 DTO 中（Uin 仅在详情中作为成员信息展示）。

## 未决

- 退出组：wx-ime-sdk 暂无该请求；补上前沿用 §5 的本地语义。
- 接入形态：wxc 子进程、Rust 插件进程走插件 RPC，或直接复用 wx-ime-sdk 协议库。
- 协议风险：wx-ime-sdk 是逆向的非官方实现，官方策略变化可能导致失效或账号限制；启用提示需据此措辞。
- 回执、成员信息与"组"在后端业务 DTO（[同步后端业务契约](../../contracts/sync-backend-contract.md)）中的表示。
