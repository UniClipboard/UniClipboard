## Context

Maintainers need low-overhead, privacy-preserving runtime visibility into CPU, memory, and mobile power behavior across desktop (`unicd`, `unic-desktop` `tray`/`gui`/`quick_panel`) and mobile (`unic-mobile` on iOS main app, iOS Keyboard Extension, and Android foreground/background service states).

Previously, [observability-contract.md §2.3](../../contracts/observability-contract.md) excluded runtime CPU, RSS, and wakeups from OTLP telemetry, limiting observations to offline E2E runs.

## Decisions (Gate 1 Approved)

1. **Extend OTLP Metrics Catalog (1A)**: Revise `observability-contract.md` (§2.3, §3.1, §14) to admit bounded resource and power telemetry strictly as Counter and Explicit-Bucket Histogram instruments under scope `unic.observability` v1, preserving PostHog `/i` Delta temporality, pathless Collector Cumulative temporality, the 4-key Resource allowlist, and the 1024-series cap.
2. **Single Desktop Exporter via Private Socket Route (2A)**: Retain `unicd` (`service.name=unicd`) as the sole OTLP exporter per desktop profile. Add an owner-only local socket route `POST /v1/diagnostics/resource-sample` (<= 1 KiB flat JSON allowlist) for `tray`, `gui`, and `quick_panel` roles to submit 60s and exit resource samples without adding OTel dependencies or exporter connections to `unic-desktop`.
3. **Reuse Existing Switches (3A)**: Reuse `telemetry.enabled && telemetry.metrics.enabled` (desktop/service) and `mobile-telemetry.json` (mobile), keeping the existing 60-second OTLP export cadence (5A) and skipping `unicd --cli-temporary` processes.
4. **Honest OS Measurement Semantics**:
   - **Interrupt wakeups vs. context switches**: `unic.power.wakeups` (`{wakeup}`) is emitted exclusively on macOS using `proc_pid_rusage(RUSAGE_INFO_V0).ri_interrupt_wkups`. Linux and Android `/proc/self/status` `voluntary_ctxt_switches` are emitted separately as `unic.power.context_switches` (`{switch}`) and never named or aggregated as hardware wakeups.
   - **Aggregate vs. per-transport network bytes**: Android `TrafficStats.getUidTxBytes`/`getUidRxBytes` measures aggregate UID traffic across all interfaces and is emitted under `unic.power.network.bytes` (`direction`, `app_state`) without guessing or duplicating across transports. iOS `MXNetworkTransferMetric` natively separates Wi-Fi and cellular counters and is emitted under `unic.power.ios_metrickit.network.bytes` (`direction`, `transport`).
   - **Separate System Battery Drain Rate (4A / Replan A1)**: `unic.power.system_battery.drain_rate` (`{percent}/h`) is explicitly documented as a system-wide reading (affected by other apps and screen brightness). Under approved Replan Decision **A1**, Android retains `system_battery.drain_rate` guarded by continuous per-value broadcast monitoring (`ACTION_BATTERY_CHANGED` + `ACTION_POWER_SAVE_MODE_CHANGED`, resetting on any plug/unknown/rise/mode/app-state/gap change, and retrying registration on 60s ticks without backdating); **neither iOS role emits `system_battery.drain_rate`** (`battery_probe_status="unsupported"`): the main app (`mobile_app`) retains `power_source` labels, real-time CPU/memory/thermal residency, and 24h MetricKit summaries, whereas the keyboard extension (`ios_keyboard`) collects CPU and memory footprint with `power_source="unknown"` (no thermal or MetricKit fields) because UIKit coalesces background notifications, quantizes `batteryLevel` in 5% steps while suspended, and extensions cannot run `MXMetricManager`.
   - **Explicit probe health & C1 Silent Backpressure Discard**: Missing/unsupported probes (`TrafficStats.UNSUPPORTED`, Android API < 29 thermal status, iOS battery drain under A1, Windows/iOS unsupported wakeups) increment `unic.resource.probe_status` (`unsupported` or `error`) and are never zero-filled. Under approved Replan Decision **C1**, cumulative counter windows invalidated by multi-state switches, transition-queue overflow, or dequeue spill above threshold (`> max(25ms, min(250ms, 0.10 * prevDur))`) are silently discarded on the host while re-anchoring baselines without adding new enums or synthetic error counts.
5. **Cross-Queue Event Timestamping & Android Mode Piecewise Residency**: Desktop `SetAppState` and Android monitor/lifecycle/screen/multicast transitions capture timestamps synchronously in bounded memory queues without running OS probes or blocking callbacks. Android `unic.power.bg_mode.time` emits piecewise wall-clock segments (`power_samples`) accurately while `background_screen_off` permits normal standby CPU deep sleep without false `sleep_jumped` resets.
6. **MetricKit Consent Generation & B1 Durable Go-Admission Boundary**: `MetricKitSubscriber` binds `(telemetryEnabled, entryGeneration)` synchronously at `didReceive` entry and uses privacy-safe SHA-256 content hashes (including interval, `latestApplicationVersion`, `includesMultipleApplicationVersions`, and canonical sanitized metrics) for deduplication. Under approved Replan Decision **B1**, payloads accepted by an enabled generation are atomically persisted to `pending-metrickit.json` before async dispatch, explicitly validated by Go `RecordMetricKit`, recorded into `seen-metrickit-ids.json` upon Go admission success, and pruned from pending afterwards; disabling clears `pending-metrickit.json` while retaining bounded `seen` digests. Downstream OTLP HTTP upload stays best-effort per §1 #9.

## Non-Goals

- Collecting device identifiers, installation IDs, clipboard content, paths, process command lines, or high-cardinality labels.
- Introducing OTel or OS probes into public `engine/` SDK or UI dependencies into `unic`/`unicd`.
- Measuring external Go plugin subprocesses (`internal/pluginproc`) or iOS Share Extension.
- Adding new Android/iOS manifest permissions or changing the 60s OTLP export period in this phase.
