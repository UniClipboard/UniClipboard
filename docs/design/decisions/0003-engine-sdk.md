# 0003 · 独立 Engine：统一接口与契约，先迁移桌面

- 状态：已采纳；阶段一（公开 `github.com/uniclipboard/unic/engine` 的全部契约）与阶段二（桌面迁移、删除旧逻辑）已完成；移动端接入仍是后续阶段（实现细节见契约第 14 节）
- 日期：2026-11-07
- 关联：[0001 配对](0001-pairing-code.md)、[0002 配置](0002-config-file.md)
- 详细规范：[Engine 公共契约 v0.1](../engine-contract.md)（接口、数据模型与行为约束；部分实现，见其第 14 节）

## 背景与目标

Engine 将用于桌面、Android、iOS 和原生鸿蒙（HarmonyOS NEXT）。目前没有搭建移动端环境，因此先定义公共接口与行为契约，再把现有桌面端迁移到该接口。移动端绑定、工具链验证和真机接入作为后续工作，不作为本次桌面迁移的前置条件。

现有 `internal/engine` 已通过 `Transport` 和 `clip.Board` 隔离网络与剪贴板，但仍依赖具体 SQLite Store、配置文件 Manager、剪贴板轮询和绝对文件路径。设备身份、网络启动、资源清理与退出则由 daemon 拼装。直接移动目录无法形成完整 SDK。

目标是复用配对与信任规则、会话管理、同步策略、内容传输和防回环逻辑，统一业务语义。各平台负责系统集成；核心可复用不代表各平台具有相同的后台运行、剪贴板权限或自动同步能力。

## 决策

### 1. 公共 Go SDK 与平台宿主

在当前仓库、当前 Go module 内提供公开的 `engine` 包（`github.com/uniclipboard/unic/engine`），先不拆仓库和独立 module。公共包可以使用内部实现，但公开类型和签名不得引用 `github.com/uniclipboard/unic/internal/*`、mygo、tailcat、SQLite 或配置文件 Manager 的类型。

```text
桌面 CLI / GUI                         未来移动端 UI
      │                                    │
桌面 HTTP 适配                         平台 SDK 绑定
      └──────────── 统一 Engine API ────────┘
                           │
             配对 / 信任 / 会话 / 同步策略 / 资源管理
                           │
                    传输与持久化实现

平台宿主：剪贴板、权限、主线程、生命周期、通知、分享入口
```

- Go SDK 使用类型化方法和 DTO，避免以一个通用 JSON 命令入口代替业务接口。
- 桌面继续使用 `unicd` + 本地 HTTP/socket，CLI/GUI 经 HTTP 适配调用 SDK；手机未来可进程内嵌入，不要求运行本地 HTTP 服务。
- 跨语言绑定是薄封装，映射同一套契约。Go 的 context、channel、interface、流等不承诺直接导出给其他语言；后续绑定转换为句柄、取消操作和事件队列。
- 统一业务契约不等于统一二进制 ABI。本阶段不冻结 C ABI、gomobile 或鸿蒙桥接方案。

### 2. 核心与宿主职责

| Engine 负责 | 平台宿主负责 |
|---|---|
| 设备身份、配对码、待批准设备、信任持久化 | 展示配对码、指纹及批准/拒绝操作 |
| 会话、重连、协议、同步过滤与大小限制 | 告知运行状态、网络变化与可用能力 |
| 提交内容、接收内容、资源生命周期、防回环 | 获取系统剪贴板、监听或轮询、写入系统剪贴板 |
| 结构化配置的验证与原子更新 | TOML、文件监听、环境变量、设置 UI |
| 状态快照、结构化事件、错误码 | UI、托盘、通知、日志输出与主线程调度 |

默认实现继续使用 tailcat 和 SQLite。存储、传输通过内部边界隔离，允许测试替换，但本阶段不要求平台自行实现数据库或网络栈，也不为尚未验证的移动平台设计大量公开插件接口。

Engine 内部允许使用私有目录和真实文件；禁止要求公共调用者必须提供系统绝对路径。路径和 URI 的转换发生在宿主或资源导入适配中。

### 3. 公共接口草案

下表是能力摘要；具体签名、补充操作与行为以 [Engine 公共契约](../engine-contract.md) 为详细规范。实现前应同步修订文档，不能仅以代码暗中改变契约。

| 能力 | 操作草案 | 契约 |
|---|---|---|
| 创建与生命周期 | `New`、`Start`、`Stop`、`Close` | 明确所有权、启动完成点、失败回收和停止等待 |
| 运行条件 | `SetRuntimeState`、`NotifyNetworkChanged` | 宿主允许核心工作；不授予系统权限，也不保证进程常驻 |
| 查询 | `GetState`、`GetCapabilities` | 返回不含秘密的可恢复状态快照与有效能力 |
| 配置 | `UpdateSettings` | 验证全部通过后原子替换，失败保留上一份 |
| 配对 | `CreatePairingCode`、`CancelPairingCode`、`JoinByCode`、`PairByAddress` | 复用 0001 的有效期、一次性、审批及指纹规则 |
| 设备 | `ListPeers`、`ListPending`、`Approve`、`Reject`、`Unpair` | 以稳定设备 ID 操作；审批不能由发现或介绍隐式完成 |
| 地址导出 | `ExportPairingAddress` | 显式返回敏感地址，普通状态查询不返回 |
| 内容资源 | `ImportContent`、`ReleaseContent` | 内存表示复制进核心；文件可复制（流）或引用（宿主提供的打开器），生成内容 ID |
| 内容发送 | `SubmitContent` | 提交内容 ID 和来源信息，返回操作 ID；不隐式读写系统剪贴板 |
| 内容接收 | `ListReceived`、`ReadContent` | 接收内容可查询并读取，不依赖订阅者一直在线 |
| 应用确认 | `ReportApplyResult` | 宿主报告写入成功、失败或延迟，核心据此更新状态与防回环信息 |
| 事件 | `SubscribeEvents` | 状态变化通知，可通过快照恢复；不作为唯一任务存储 |

`ImportContent` 完成代表内存表示已复制进核心；文件有两种输入：流（复制到核心拥有的目录）和引用（宿主提供 `FileSource` 打开器，核心只记录名称和大小，不复制、不占存储配额）。失败必须清理半成品。导入、提交分开；引用的文件在传输开始时重新打开并校验大小与版本，被修改或删除则这次发送以 `source_changed` 失败，不会发出不一致的数据。桥接层的大文件读取采用分块/流，不把文件整体转换成 JSON 或跨语言字节数组。公开 API 不接收路径：桌面适配器用路径实现打开器，移动端用 URI 实现。

### 4. 生命周期与并发

- 一个实例独占一个数据目录；同目录重复打开必须报错，不能启动两个独立身份或并发清理彼此的资源。
- `New` 验证选项并准备本地资源，不启动网络；`Start` 成功代表核心已开始接受工作，不代表已与任何远端连通。
- 状态为 `created → starting → running → stopping → stopped → closed`。启动失败回到可关闭的 `stopped`；同一实例停止后不重新启动，恢复使用运行条件更新，完全重启创建新实例。
- `Start` 重复调用返回状态错误；`Stop`、`Close` 幂等。`Close` 包含停止与释放自身持有的存储、传输和订阅资源。
- `Stop` 取消重连，关闭监听与会话，等待核心工作退出。等待超时返回明确错误，此时仍为 `stopping`，不得提前关闭仍在使用的存储；调用者可以继续等待。
- `SetRuntimeState` 的 active/suspended 表示宿主是否允许网络工作。suspended 关闭网络会话并暂停新传输；active 重新监听和重连。它区别于 `sync.enabled=false`：后者按 0002 保留连接，仅禁止内容同步。
- 首版不承诺断点续传；挂起或断网中断的在途传输标记失败，不在恢复后自动发送过期剪贴板。宿主恢复观察时重新建立本地基线。
- 公共方法允许并发调用；状态变更由核心串行化。阻塞操作支持 context 取消；已持久化的信任决定或已提交的操作不会因调用者取消而自动回滚，结果可查询。
- 核心不调用平台 UI API，不要求宿主在 Go 工作线程操作剪贴板。事件消费和主线程调度由宿主完成，不能在持锁期间执行宿主代码。

### 5. 内容、应用与防回环

- 内容由同一项目的多种 MIME 表示（如 UTF-8 文本、HTML、PNG）及文件组成。明确保留 MIME 和字节，不依赖 mygo 格式枚举；首版延续现有单项目模型，不新增任意多项目剪贴板协议。
- 内容具有稳定 ID，文件以名称、大小和资源 ID 描述。绝对路径、Android URI 等平台定位符不进入设备间协议和公共业务 DTO。
- 核心沿用协议硬上限，并在导入及提交时验证；接收超出用户限制仍按 0002 读完并丢弃，保持连接。实际可用能力还取决于宿主支持的格式与当前权限。
- 本地内容提交成功只表示核心已接管发送请求。状态区分 `queued`、`sending`、`sent`、`failed`、`superseded`；慢连接允许只保留最新待发送内容，被替换者必须标记为 `superseded`。
- `sent` 只表示本机已写完协议数据，不表示远端已接收或写入剪贴板。当前 wire 没有对应 ACK，本阶段不伪造这两种保证，也不为此修改 wire。
- 接收状态区分内容可用和本机已应用。宿主可自动应用、等待用户操作或报告失败；写入失败不标记为成功，也不阻断其他内容接收。
- 桌面轮询移至剪贴板适配层；启动时先读取为基线，不广播旧内容。CLI 的显式发送可以绕过基线过滤，直接提交一次，不再依赖下一次轮询发现写入。
- 远端应用使用 apply token 关联内容及应用结果。宿主成功写入后提交实际剪贴板表示的基线，并将对应观察变化关联到该 token，避免系统补充格式造成回传。失败不推进成功基线。并发应用需序列化或以代次拒绝过期结果，不能把期间的新本地复制误吞。
- 内容 hash 用于内容标识/去重，不作为跨设备冲突时钟；首版保留现有最新剪贴板语义，不增加历史合并或按设备时钟排序。
- 当前文件 hash 只包含名称与大小，不能证明文件字节相同。首版明确这一限制，不宣称文件内容校验；引入内容摘要需要另行处理 wire 兼容，不夹带在本次抽离中。

### 6. 资源所有权与清理

- 内存表示导入后宿主可释放原始流，传输使用核心拥有的不可变副本。引用的文件不是副本：宿主必须在内容被租约或操作引用期间保持其可打开，否则相关发送失败。接收的文件来自网络，始终是核心拥有的磁盘文件。
- 接收文件在应用或用户使用期间需有显式保留引用。`ReleaseContent` 释放调用者引用，核心仅在无传输、接收列表保留或宿主引用时回收；重复释放不重复扣减。
- 桌面适配保留当前已写入剪贴板文件的引用，确认被新内容替换后再释放；不由 engine 猜测系统是否还在使用文件。
- 配置有界的接收保留策略和磁盘配额；首版接收列表只保证当前实例内可恢复查询，不承诺历史记录或进程退出后的待应用投递。资源不足应报告失败，不能无界积累或删除仍有引用的文件。
- 启动清理仅处理核心明确拥有且无有效保留的资源。迁移时处理旧 `clip-*` 布局，继续遵守 0002：绝不删除用户整个 inbox。不得通过任意调用者路径执行递归删除。

### 7. 配置、状态、事件与错误

- SDK 配置为类型化值，配置文件解析和监听留在桌面层。0002 中现有默认值、生效时机、坏配置保留、inbox 需重启等行为保持；打开实例的数据目录与 inbox 属于创建选项，不能在运行中切换。
- 平台报告自身支持的格式、观察/应用能力与当前授权、可运行状态；引擎计算有效能力。静态“不支持”与暂时“无权限/不可用”须区分，不能用统一成功掩盖降级。
- 状态快照包含实例 ID、修订号、生命周期、设备、待审批项、当前配对码状态、操作和待应用内容。秘密地址与票据不包含在内。
- 事件包含实例 ID、单调递增序号、种类、相关对象 ID 和 Unix 毫秒时间；顺序以序号为准。时间用于展示，不用于信任和全局排序。
- 订阅返回初始快照及之后的事件，消除查询与订阅间隙。通知队列有界，溢出必须标记需要重新同步，消费者重新获取快照；操作和待应用内容不能随通知丢失。关闭订阅必须可重复且结束消费等待。
- 事件不携带完整内容、秘密或自由文本剪贴板摘要。通过显式内容读取展示用户数据；默认日志也不记录剪贴板正文。
- 错误包含稳定 code、可安全展示的 message 和是否可重试。至少覆盖 `invalid_argument`、`invalid_state`、`closed`、`not_found`、`unsupported`、`permission_denied`、`resource_expired`、`limit_exceeded`、`resource_exhausted`、`unavailable`、`timeout`、`cancelled`、`internal`，以及 0001 已有配对码错误分类。等待对方批准是配对结果状态，不作为传输故障反复提示。
- 所有错误与日志边界必须脱敏，包括第三方网络错误；不得直接转发可能包含地址、票据或正文的底层错误。

### 8. 信任与版本兼容

- 延续 0001：配对码只定位地址，出码方必须批准并核对指纹；第三方介绍不能授予信任。完整地址主动配对保留现有信任语义。
- 不向公共 DTO 暴露存储中的 Peer 地址。地址仅通过显式配对导出返回，禁止进入事件、错误和日志。
- SDK 契约版本、桌面 HTTP 版本、设备 wire 版本分别管理。本阶段保留当前 wire v2；不因更换本地 API 强迫其他设备升级。
- 桌面 `/v1` 通过适配层保留已有响应形状；旧地址字段如必须保留，仅限现有显式 HTTP 响应，不复制到新 SDK 通用状态或事件。新增状态不应被旧客户端误解释为发送/应用成功。
- 新 SDK 稳定发布前允许在迁移中调整签名，但必须维护文档和契约测试；稳定后不以补丁版本改变方法语义。未来绑定沿用同一业务契约，具体类型映射由绑定方案说明。

## 实施顺序与验收

### 阶段一：契约落地

1. 定义公开 DTO、配置、生命周期、错误码及查询/订阅模型，公共签名不泄漏内部类型。
2. 把现有配对、过滤、信任测试迁移或补充为契约测试；用假传输、假宿主和临时目录验证，无需移动端环境。
3. 验证启动失败回收、停止等待、关闭后调用、并发调用、事件溢出恢复、资源释放及脱敏。

### 阶段二：桌面迁移

1. 封装默认 SQLite、tailcat、身份与目录生命周期，使 daemon 只负责装配宿主适配。
2. 将轮询、系统写入和防回环观察关联移到桌面适配；替换依赖 watcher 的 `SetLocal` 行为。
3. 配置文件 Manager 调用结构化更新接口；HTTP Handler 调用公开 SDK，CLI/GUI 保持现有交互。
4. 删除旧 engine 入口或将其并入内部实现，确保只有一套业务状态和信任逻辑。

验收标准：

- `go build -o unic ./app/desktop/cmd/unic && go build -o unicd ./app/desktop/cmd/unicd`（布局调整后的路径，见 0005）与 `go test -race ./...` 通过。
- 两个桌面节点验证文本、HTML、PNG、文件同步及防回环，启动不广播已有剪贴板。
- 验证完整地址配对、配对码、指纹、批准/拒绝、介绍、移除设备与重启后信任保留；移除设备同时释放相关连接资源。
- 验证暂停、类型过滤、超限、断线重连、配置热加载、坏配置保留和 inbox 重启提示。
- 验证写入失败、并发远端应用、本地复制穿插、慢订阅者及文件被替换后的资源回收。
- 桌面不直接操作核心 Store、tailcat 或内部会话；平台剪贴板不被核心直接调用。

### 后续阶段：移动端接入

准备环境后分别验证 Android/iOS 绑定、原生鸿蒙 Go runtime 与 Native 桥接、tailcat/SQLite 兼容性、网络恢复和资源释放；再以真实平台约束修订适配能力。首先接入前台文本发送与接收应用，再扩展图片、文件和系统允许的后台场景。

本决策扩展 0001 的长期目标平台；0001 的“仅桌面端”仍描述当前交付范围，其配对协议和安全规则保持有效。移动端构建成功及后台自动同步均不在本阶段验收范围。

## 本阶段不做

- 搭建移动环境、生成 AAR/XCFramework、实现鸿蒙 Native 桥接或承诺四端编译通过。
- 更换实现语言、UI 框架、tailcat 或数据库。
- 拆仓库、独立发布 SDK、冻结跨语言 ABI。
- 增加 wire ACK、断点续传、离线可靠投递、历史搜索或文件内容摘要协议。
- 为绕过系统剪贴板或后台限制引入额外权限方案。
