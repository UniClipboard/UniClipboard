# 0013 · 桌面 UI Kit：移植 React 组件契约到 mygo

- 状态：已采纳
- 日期：2026-11-09
- 关联：[0005 仓库布局](0005-monorepo-layout.md)、[执行记录](../../exec/0013-mygo-uikit.md)

## 背景

uniclipboard 的 React UI Kit 已有统一组件契约和 Linux Adwaita、macOS glass、Windows Fluent 三套皮肤。Go 桌面客户端使用 mygo，需要沿用这些组件的语义和视觉层次，同时保留原生输入、焦点和键盘交互。

## 决策

1. 将现有 UI Kit 移植到 `app/desktop/internal/uikit`，而不是另建一套组件体系或引入 WebView。以参考仓库 `main` 的 `contract.ts` 为组件清单；2026-11-09 核对的提交为 `9e41d15f7ecf2be4e3bd03327625fd2b4adbbbd5`，实际声明 59 个公共组件，早期计划中的“约 90 个”是估算。Go Kit 已覆盖这 59 个组件，并提供部分辅助组件。
2. `Kit{Skin, Dark}` 是无状态组件工厂。调用方通过 `uikit.For(dark)` 选择当前平台皮肤，在视图根调用 `UiRoot` 安装主题；`UNIC_UI_SKIN=linux|macos|windows` 允许在本机预览其他皮肤。
3. 使用 mygo 的 Base 控件实现交互，再用 Kit 的 token 绘制外观。React 的回调改为返回交互结果或修改调用方提供的状态指针；列表使用稳定 ID。应用只依赖 Kit 和 mygo 的布局原语，不在业务页面重新实现按钮、字段、分段控件和确认对话框。
4. token 从 uniclipboard 的 `themes/default.json` 生成，保留各平台、亮暗模式的原始 token。运行 `scripts/gen_tokens.py` 并用 gofmt 格式化产物；禁止手改 `tokens_gen.go`。业务和组件优先引用 token，不复制具体颜色。
5. 将 mygo 升级到 `v0.8.4-0.20261108082913-9233663736ca`。Kit 仅在桌面应用内部使用，核心 SDK 不依赖它。
6. 交互测试和视觉检查分开验收。除了三皮肤 × 亮暗模式的组件测试，GUI 测试还验证实际视图的导航、审批信息、移除确认、断线恢复、窄窗口和焦点环绘制。可通过 `UNIC_UI_TEST_ARTIFACTS` 导出截图；交互测试通过不能代替视觉检查。

## 布局与绘制约束

- 分段控件的子项必须撑满轨道的交叉轴；宽轨道中的子项分配剩余宽度，不能让选中底板退化成文字背景。
- macOS TextField 使用 22pt 高度、5pt 圆角、6pt 水平内边距。字段允许收缩，不能用固定最小宽度挤出旁边按钮。焦点采用单层 3.5pt 半透明外环，保留内部细边线。
- 绘制到控件边界之外的焦点环必须位于父容器的裁剪区域内。历史筛选栏放在滚动列表之外；其他滚动页面在视口内部保留边距。
- 空历史的占位组件分配剩余内容高度，在该区域内居中。不要依赖无界滚动内容中的 `Grow` 或百分比最小高度来获得视口高度。
- 设备审批仍须显式核对指纹；配对码只用于发现设备。设备移除使用破坏性确认对话框，初始焦点在取消按钮。

## 接受的近似

本次接受原生控件对 React 外观的近似，不要求像素一致：图标为矢量重绘；毛玻璃使用 mygo 材质与着色近似；部分进出场动画、Windows 侧栏轨、macOS 工具栏滚动渐隐未还原；表格复用 mygo 表头；网格列数依赖上一帧宽度；部分浮层宽度和位置采用固定策略。各分组细节见执行记录。

三皮肤在同一宿主的离屏渲染覆盖布局和绘制，不能证明 Windows/Linux 的原生窗口、字体、输入法和平台辅助功能已经验收。
