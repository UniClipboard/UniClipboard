# 后台内存预算与验收

后台内存应同时区分活跃分配、分配器保留空间、文件映射和处理峰值。以图片负载后静置120秒的 PSS 观察常驻表现，同时保留 RSS、匿名 PSS、入库延迟和完成数量；不得把配置的缓存上限、累计分配或虚拟地址空间当作常驻量。

## 默认策略

- Engine 对剪贴板传输负载使用单线程 Zstd 整块压缩，不为每次图片发布创建按 CPU 核数扩展的压缩线程池。压缩等级、既有压缩选择规则与加密格式保持不变。大块不可压缩输入仍会尝试压缩，Port 不据内容类型猜测可压缩性。
- Linux/glibc 的 `uniclipd` 在创建后台工作线程之前限制分配器内存区数量，并固定大块分配阈值，使临时大缓冲释放后可以归还系统。该策略只属于 daemon 宿主，其他平台使用各自分配器。
- 宿主 JSON 日志队列容量为8,192条。普通滚动日志保持异步、有损队列；诊断精确日志文件保持阻塞式无损队列，退出仍由原有 `WorkerGuard` 刷盘。

分配器参数的具体默认值由 `apps/daemon/src/allocator.rs` 维护。操作者提供的 `MALLOC_ARENA_MAX`、`MALLOC_MMAP_THRESHOLD_` 或 `GLIBC_TUNABLES` 中对应的 `glibc.malloc.arena_max`、`glibc.malloc.mmap_threshold` 优先；覆盖其中一项不会阻止另一项使用默认策略。

```bash
MALLOC_ARENA_MAX=8 uniclipd
GLIBC_TUNABLES=glibc.malloc.arena_max=4:glibc.malloc.mmap_threshold=262144 uniclipd
```

固定大块分配阈值会增加部分 `mmap`/`munmap` 调用，减少分配器内存区的长期保留；限制内存区数量也可能增加高并发分配争用。验收必须同时观察处理延迟，不按内存单项判断收益。语义依据见 [glibc 分配器参数](https://sourceware.org/glibc/manual/latest/html_node/Malloc-Tunable-Parameters.html)。

## 复测要求

1. 使用去符号优化构建，旁路符号只提供给离线分析工具。Rust 错误调用栈解析会加载调试信息，带符号二进制的常驻量不能代表安装版。
2. 使用独立加密测试资料和合成图片，逐张确认 `BlobReady`，同时采集 PSS/RSS、可用内存与 OOM 计数；不得读取或记录私人剪贴板正文。
3. 各项策略先做单变量对照，再验证组合结果。新资料初始化、正常图片处理和静置分别标记，首次初始化的 Argon2 峰值不能混为常驻量。
4. 使用相同图片尺寸和静置时长，统计中位数、尾部延迟、峰值和最终内存。无配对资料不能替代真实双设备吞吐、跨平台和长期运行验收。

本机的实验过程和未执行平台记录在 `.planning/daemon-memory/`。不降低密码学参数，不用定时强制清理替代对象生命周期与分配策略修复。

## 本机验收记录（2026-10-21）

Linux aarch64、12核，使用无配对的全新加密资料和交替尺寸合成PNG。优化前10张负载后静置末值PSS约126.9MiB；组合优化后以100张负载复测，全部确认`BlobReady`，静置120秒最后15秒平均PSS58.53MiB，整个静置阶段峰值58.54MiB，末值RSS60.78MiB。入库中位数236.6毫秒、p95为268.3毫秒，无OOM。

首次最终轮次在复制前触发系统可用内存保护，未执行负载；保留保护阈值，等待内存恢复后以新资料完成上述有效轮次。两轮数据分开保存。该结果证明本机此负载达到约60MiB目标，其他平台、真实双设备吞吐和24小时运行尚未验证。
