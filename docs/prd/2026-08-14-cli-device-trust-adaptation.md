# CLI 设备信任核对适配 PRD

## 文档状态

- 状态：草案，待产品评审
- 日期：2026-08-14
- 范围：`uniclip` 命令行工具
- 依赖产品规则：`docs/prd/2026-08-13-device-trust-reconciliation.md`

## 一句话定义

让没有 GUI 的用户也能通过 CLI 看懂当前设备信任变化、安全地作出决定，并得到与桌面 GUI 一致的设备关系结果。

## 背景

本次桌面 GUI 已接入完整的设备信任核对流程。CLI 目前只保留了主动移除设备和查看旧成员收敛摘要的能力。

这意味着纯命令行、远程服务器和无桌面环境中的用户可以看到“存在待处理决定”，却无法知道谁提出了变化、哪些设备受影响，也无法完成决定。设备间同步因此可能长期暂停，用户必须转到 GUI 才能继续。

CLI 是 UniClipboard 的正式产品入口，不是只供诊断使用的工具。相同的设备信任事实和决定，在 GUI 与 CLI 中必须得到相同结果；两者只在交互形式上不同。

## 目标用户

- 在 Linux 服务器、无桌面系统或 SSH 会话中使用 UniClipboard 的用户。
- 偏好终端管理设备的桌面用户。
- 通过脚本监测设备状态，但由人明确批准安全决定的运维用户。
- 需要在自动化环境中提交预先审核决定的高级用户。

## 用户任务

用户需要能够：

1. 判断当前是否有设备信任变化等待处理。
2. 看清哪台设备提出变化、要移除哪些设备，以及本机是否在其中。
3. 比较两种选择分别会让哪些设备继续同步、暂停同步或需要重新加入。
4. 明确选择应用变化，或保留本机当前设备组。
5. 在状态已经改变、决定已处理或提交失败时，知道真实结果和下一步。
6. 在脚本中稳定读取状态，不被提示、颜色或说明文字干扰。

## 产品原则

### 与 GUI 结果一致

CLI 和 GUI 必须读取同一份完整当前结果，并提交同一种用户决定。CLI 不得根据旧状态、在线情况或设备数量自行推断关系、影响或允许动作。

### 查询与决定分开

查看状态永远不修改设备关系。决定命令必须明确包含用户刚刚审核的变化编号和选择，避免误处理已经变化的任务。

### 重大后果需要明确确认

保留当前设备组会导致部分设备进入不同空间；应用包含本机的移除会让本机退出原空间。交互式终端必须在提交前再次说明后果并默认取消。

自动化调用不能依赖含糊的通用确认。移除本机必须使用专门确认参数；其他决定可以使用显式的非交互确认参数。

### 脚本不会被交互阻塞

JSON 模式和非交互终端不得显示问题、等待输入或启动选择菜单。必要参数不完整时立即返回失败，并说明缺少什么。

### 输出描述结果，不暴露内部过程

人类输出使用设备名称、设备标识和同步后果，不展示成员历史、摘要、签名或内部阶段名。成功信息只说明本机决定及其结果，不声称所有离线设备已经完成同步。

## 范围

### 完整状态查询

CLI 提供固定入口读取当前设备信任状态。结果至少包括：

- 本机当前是否仍属于原空间。
- 当前是否有需要决定的变化。
- 当前变化编号。
- 提出变化的设备。
- 将被移除的设备。
- 当前允许的选择。
- 应用变化后的影响。
- 保留当前设备组后的影响。
- 每台相关设备的在线情况、成员资格、空间关系、版本兼容情况和同步关系。
- 当前无法操作时的稳定原因和可执行下一步。

没有待决定变化时，查询仍展示当前设备关系，不能只输出“没有任务”。不同空间、需要更新、无法验证和本机已退出仍是有价值的长期状态。

### 提交决定

CLI 支持两种结果导向选择：

- 应用当前设备变化。
- 保留本机当前设备组。

提交必须包含当前变化编号。CLI 只能提交后台明确允许的选择；不允许时应拒绝操作并展示当前原因，不尝试绕过。

交互式终端在提交前展示：

- 变化来源。
- 移除目标。
- 所选结果会让哪些设备继续同步或暂停同步。
- 是否会移除本机。

用户取消时不提交任何决定，并清楚说明状态没有改变。

### 本机被移除

当应用变化会移除本机时：

- 普通决定确认不足以提交。
- CLI 必须明确说明本机将退出原空间、停止与原空间同步，但本地历史仍按产品既定规则保留可用。
- 交互式终端要求第二次明确确认。
- 非交互调用必须提供专门的本机移除确认参数；通用 `--yes` 不得代替。
- 完成后展示本机已退出，以及重新加入需要新邀请。

### 保留当前设备组

用户选择保留当前设备组前，CLI 必须说明：

- 本机不会应用这项移除。
- 已经应用另一项变化的设备不会撤销其决定。
- 双方会进入不同空间并停止分享新内容。
- 同一设备组内的其他设备可以继续使用。

完成后，该结果是稳定状态，不显示为网络故障，也不建议无效重试。

### 状态变化与重复提交

决定返回后，CLI 必须区分：

- 已按本次选择完成。
- 此前已经完成相同或其他选择。
- 用户查看后状态已经变化。
- 仍需确认本机移除。

状态已经变化时，不得把命令报告为成功应用。CLI 展示最新当前结果，并提示用户重新审核新的变化编号。

重复提交同一已完成决定不得产生新的变化。输出应说明它已处理，并返回当前完整状态。

### 人类可读输出

默认输出优先回答：

1. 现在是否需要用户行动。
2. 发生了什么。
3. 两种选择的真实后果。
4. 当前每台设备为何能或不能同步。
5. 下一条可执行命令是什么。

设备名称优先，稳定设备标识同时显示，便于名称重复时确认对象。长标识不得作为唯一识别信息。

所有 CLI 可见文案使用英文，保持现有产品约定。

### JSON 输出

全局 `--json` 适用于查询和决定命令，并满足：

- 标准输出只包含一个完整 JSON 文档。
- 不输出标题、提示、进度动画或确认问题。
- 错误和诊断文字只进入标准错误。
- 字段名和值保持稳定，可被脚本长期解析。
- 查询返回完整当前结果；决定返回明确决定结果及决定后的完整当前结果。
- 人类输出的后续建议不得替代结构化的允许动作和不可用原因。

### 命令结构

目标命令体验为：

```text
uniclip member trust
uniclip member trust decide --change <CHANGE-ID> --choice <apply|keep-current>
```

非交互提交额外使用明确确认参数：

```text
uniclip --json member trust decide \
  --change <CHANGE-ID> \
  --choice apply \
  --yes
```

当变化包含本机时还必须增加：

```text
--confirm-local-removal
```

具体短参数、帮助排版和内部组织由实现规格确定，但公开命令含义不得偏离本节。

### 旧命令兼容

- `uniclip member remove <PEER-ID>` 继续作为本机主动移除设备的公开入口。
- 主动移除成功后应展示新的完整设备关系结果，不能只展示旧收敛阶段。
- `uniclip member removal-status` 在兼容期继续可用，输出明确引导用户改用 `uniclip member trust`。
- 旧命令的 JSON 结构在兼容期不得静默替换。新脚本必须使用新的设备信任入口。
- 移除旧命令需要单独发布说明和明确版本计划，不属于本次适配的强制范围。

### 总体状态提示

`uniclip status` 应把需要用户决定、需要更新、本机已退出或存在无法验证资料作为清楚的产品状态展示，并引导用户运行设备信任查询。

总体状态只负责提醒，不复制完整详情，也不提供决定动作。

## 命令结果与退出行为

CLI 的结构化结果与退出行为结合后，必须让脚本区分以下情况：

- 查询成功，包括“没有待决定变化”。
- 决定完成或此前已完成。
- 用户取消，且没有修改状态。
- 当前存在待决定变化，但本次只是成功查询、尚未处理。
- 状态已经变化，需要重新审核。
- 缺少必要确认、选择不可用或参数错误。
- 后台不可达或处理失败。

具体数值由实现规格统一定义，并复用项目现有退出码管理位置。不得在各命令中各自发明数值。JSON 中同时提供稳定结果类别，脚本不应只能依赖自然语言判断。

## 异常与边界情况

- 后台不可达：不读取本地缓存冒充当前状态，说明后台不可用。
- 没有待决定变化：决定命令拒绝提交，并返回最新状态。
- 变化编号过期：不自动改用当前变化编号。
- 选择不在允许列表：不提交，并说明当前允许选择。
- 设备名称重复：始终同时显示稳定设备标识。
- 设备离线：只显示离线，不推断为不同空间或需要更新。
- 对方版本过旧：说明应在哪台设备更新，不能暗示 CLI 可以远程更新。
- 资料无法验证：说明同步已暂停且当前无可执行恢复动作，不提供无效重试。
- 输出被管道接收：不显示颜色、动画或交互问题。
- 用户按下中断键：若尚未提交则不改变状态；提交已发出时重新查询并报告可确认的最终状态，不能猜测成功或失败。

## 隐私与安全

- CLI 只展示完成决定所需的设备名称、稳定设备标识、关系和影响。
- 不展示或记录成员历史、签名、摘要、密钥、网络地址、文件名、路径或剪贴板内容。
- 默认日志不得记录完整设备关系图、变化目标或用户选择详情。
- CLI 不额外持久化查询快照、决定队列或设备名称。
- Shell 历史可能保存命令参数，因此决定参数不得包含密钥、密码或其他秘密；设备标识和变化编号按非秘密但可关联信息处理。

## 非目标

- 不在 CLI 中实现设备信任业务规则或维护第二份状态。
- 不提供自动接受所有未来变化的开关。
- 不根据在线状态、设备数量、时间或版本替用户决定。
- 不增加账号、管理员、主设备或服务器审批模型。
- 不在本次适配中提供不同空间的自动合并。
- 不让 CLI 常驻监听并自动弹出决定；用户通过查询、总体状态或外部监控发现任务。
- 不改变 GUI 已确认的产品语义。

## 交付要求

完整 CLI 适配需要同时交付：

- 完整状态查询命令。
- 两种决定及本机移除确认。
- 人类可读输出和 JSON 输出。
- 清楚且稳定的退出行为。
- 总体状态提示。
- 旧命令兼容说明。
- CLI 帮助和 `apps/cli/README.md` 文档。
- 命令解析、输出、异常结果和后台交互测试。
- 至少一个真实多设备或等价端到端验收，证明 CLI 作出的决定会改变接收端的实际同步关系。

## 验收标准

### 查询

1. 没有待决定变化时，命令成功并展示当前设备关系。
2. 有待决定变化时，准确展示来源、目标、本机是否受影响、允许选择和两种选择的影响。
3. 不同空间、需要更新、无法验证、本机已退出和普通离线得到不同且准确的说明。
4. 名称重复时，用户仍能通过设备标识确认对象。
5. JSON 查询只输出一个完整且可解析的文档。

### 决定

6. 用户可以通过 CLI 应用当前变化，完成后看到新的完整状态。
7. 用户可以保留当前设备组，完成后相关设备明确显示为不同空间。
8. 未提供变化编号、编号过期或选择不被允许时，状态不会被修改。
9. 应用会移除本机的变化时，缺少专门确认参数无法在非交互模式提交。
10. 交互式本机移除具有第二次确认，并默认取消。
11. 用户取消不会修改状态，也不会被报告为完成。
12. 重复提交不会产生第二项变化，并返回真实的已完成结果。
13. 提交期间状态变化时，旧选择不会应用到新变化，用户能看到最新状态。

### 脚本与终端

14. `--json` 和非交互终端从不等待输入。
15. JSON、错误和提示分别进入正确输出通道，管道解析不受干扰。
16. 查询、完成、取消、待处理、状态变化、参数错误和后台不可达可被稳定区分。
17. 输出被重定向时没有颜色控制符或动画残留。

### 兼容与一致性

18. `member remove` 继续可用，且结果不再依赖旧收敛摘要解释完成状态。
19. `member removal-status` 在兼容期行为稳定，并清楚引导新入口。
20. `uniclip status` 能提醒存在需要处理的设备信任问题，但不复制决定流程。
21. CLI 与 GUI 对同一快照展示相同的变化来源、目标、允许选择和最终设备关系。
22. CLI 与 GUI 分别提交同一变化时，重复操作得到一致且安全的结果。

### 端到端结果

23. CLI 应用设备移除后，目标设备不再收到本机发送的新内容。
24. CLI 保留当前设备组后，不同空间的设备彼此不再收到新内容，同组设备继续同步。
25. 本机通过 CLI 确认退出后，原空间不再收到本机新内容，本机仍可按既定规则独立使用。
26. 设备离线、后台重启或 CLI 中断后，重新查询仍得到后台保存的真实状态。

## 成功标准

本适配完成的判断不是“CLI 能调用新接口”，而是：用户仅使用 CLI 就能发现、理解、决定并验证设备信任变化，不需要打开 GUI，也不会因脚本或过期状态误作安全决定。

## 待产品评审

1. 用户取消决定时，是否统一返回成功，还是使用独立的非零退出结果？建议使用独立结果，避免脚本误认为决定已完成。
2. 只读查询发现待决定变化时，默认是否仍返回成功？建议返回成功，并在 JSON 中表达待处理状态；另提供适合监控的明确选项或后续命令，避免改变普通查询语义。
3. `member removal-status` 的兼容周期按几个正式版本计算？建议至少保留一个正式版本，并在帮助和运行输出中提示迁移。
