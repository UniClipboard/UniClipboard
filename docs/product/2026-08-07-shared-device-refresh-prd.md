# 主动刷新共享设备 PRD

## 文档状态

- 状态：草案，待产品评审
- 日期：2026-08-07
- 范围：桌面端设备页

## 背景

用户的新设备完成与某一台已有设备的配对后，仍可能不知道同一 Space 中的其他设备。例如，A 已配对 C，B 新与 A 配对；此时 B 不会自动拥有 C 的连接资料。

用户需要一个主动入口，让 B 向当前已配对设备查询可共享的设备，并由产品自动完成后续连接。这个动作只处理设备关系，**不传输剪贴板、历史、文件或任何最新内容**。

## 目标

- 用户一次点击即可发现并自动连接本机尚未连接的共享设备。
- 用户能看到实际发现了哪些设备，以及每台设备当前的结果。
- 离线或暂不能连接的设备由后台继续处理，用户无需重复操作。
- 已连接的设备自动出现在设备页列表中。

## 非目标

- 不同步剪贴板内容、历史或文件。
- 不要求用户选择设备、逐台确认或输入任何信息。
- 不提供取消正在进行刷新的能力。
- 不提供手动重试单台设备的能力。
- 不因设备暂时不可达而改用其他传输方式。
- 不展示设备地址、身份信息、底层失败原因或其他敏感资料。

## 用户入口

入口位于设备页的“已配对设备”区域标题右侧，使用刷新图标，悬浮说明为“刷新共享设备”。

- 至少存在一台已配对设备时展示入口。
- 没有已配对设备时不展示入口，因为没有可查询的来源。
- 刷新进行中，入口保持可见并显示进行中状态；再次点击只重新打开当前结果窗口，不发起另一轮工作。

## 核心交互

### 发起

用户点击入口后，立即开始自动刷新并打开进度窗口。窗口初始显示“正在查找可连接设备”。

点击不弹出确认，不要求用户选择设备，也不提供取消按钮。用户只能关闭窗口；关闭窗口只关闭展示，后台工作必须继续。

开始时产品尚不知道会发现哪些设备，因此不得预先声称某台设备“将会配对”。设备被发现后才加入窗口列表，只有显示“已自动连接”才代表连接已经成功。

### 进行中

窗口显示已发现设备的名称和逐台状态。设备按后台提供的稳定顺序展示；同一设备只显示一行，状态变化更新原行。

| 后台状态 | 用户文案 | 用户含义 |
| --- | --- | --- |
| 已发现 | 已发现，正在准备连接 | 已从可信的已配对设备获知该设备，尚未完成确认。 |
| 连接中 | 正在自动连接 | 正在确认并建立连接。 |
| 已连接 | 已自动连接 | 已成功加入本机的已配对设备。 |
| 已存在 | 已在本机设备中 | 本机原本已连接该设备，不重复处理。 |
| 等待上线 | 等待设备上线，会继续尝试 | 设备暂时不可达，后台会在其上线后继续。 |
| 等待更新 | 等待资料更新，会继续尝试 | 需要等待已有设备资料更新后才能继续。 |
| 版本不兼容 | 版本不兼容 | 当前无法与该设备建立连接。 |
| 已拒绝 | 无法连接 | 该设备未通过必要校验，不能加入本机。 |

若某些已配对设备暂时无法回答查询，窗口只显示“部分已配对设备目前不可用”，不显示其名称或底层错误。其他可用来源仍应继续处理。

### 首轮完成与后续变化

首轮查找及即时连接完成后，窗口显示“本轮查找完成”，并保留完整结果，由用户手动关闭。窗口不得自动关闭。

- 没有发现新设备时，显示“未发现可自动连接的设备”。
- 发现设备但都已存在时，清楚显示它们已在本机，无需重复连接。
- 存在“等待设备上线”或“等待资料更新”时，首轮仍可完成；后台继续处理这些设备。
- 用户未关闭窗口时，后续状态变化继续更新窗口。
- 用户已关闭窗口时，后续成功连接仍应更新设备页的已配对设备列表；不发送额外系统通知。

### 异常与中断

- 无法开始刷新时，保留当前设备页，并提示“暂时无法开始刷新”。不得展示原始错误内容。
- 后台服务重启后，原进度不再可查询。若窗口仍打开，显示“刷新状态已结束，请重新刷新”，用户关闭窗口后可从入口重新开始。
- 网络短暂中断、个别设备离线或设备版本不兼容，都不得中止其他设备的处理。

## 产品行为约定

产品端只承担发起、查询当前结果和展示状态的职责，不自行拼接设备发现、确认、保存或重试步骤。

每次发起会得到一个本轮刷新编号。产品端收到状态变化提醒后，必须重新读取该编号的完整当前结果，而不是依赖此前收到的零散过程消息。这样即使窗口晚打开、恢复前台或短暂断开，也能显示后台当前的真实状态。

重复发起同一轮刷新时，后台返回正在进行中的同一轮结果；产品端据此复用当前窗口和状态，不产生重复查询或重复连接。

## 隐私要求

窗口和错误提示仅可展示设备名称、稳定设备标识和上述状态。不得展示或记录剪贴板内容、网络地址、身份指纹、签名、安全资料或底层网络错误原文。

## 验收场景

1. A 已与 C 配对，B 新与 A 配对；B 点击“刷新共享设备”后，先看到 C 被发现，随后显示“已自动连接”，并且 C 自动出现在 B 的已配对设备列表中。
2. C 离线时，B 显示“等待设备上线，会继续尝试”，不把 C 标记为已连接；C 恢复上线后，后台继续完成连接，不要求 B 再次点击。
3. 用户在刷新过程中关闭窗口，后台仍继续；成功后设备页列表更新，且没有额外系统通知。
4. 用户连续点击刷新入口，不出现多份进度窗口或重复连接；窗口展示同一轮的最新结果。
5. 没有新设备时，用户看到明确结果；已存在、版本不兼容和无法连接的设备均不被误报为“已自动连接”。
6. 窗口晚打开或状态提醒延迟时，显示的设备和状态仍与后台当前结果一致。
7. 所有窗口文案、日志和展示结果均不包含剪贴板内容、网络地址或底层错误原文。

## 后续实施边界

本 PRD 确认后，桌面端需要接入 Engine 的“发起刷新”“读取当前结果”和“状态变化提醒”三项能力，将结果送到设备页。连接成功的唯一判定来自后台的“已连接”状态；前端不得自行推断成功。
