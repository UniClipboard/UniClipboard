- **日期**：2026-09-07。
- **状态**：已实施，验收未全部通过。逐项依据见[验收报告](../../.planning/device-group-choice-gui/verification.md)，未通过项不得计为完成。
- **交付范围**：设备组选择窗口重设计、新版 Engine 展示资料接入、可复用的本机四至五配置测试数据、真实桌面界面端到端测试。
- **测试平台**：本机 macOS，同时运行四至五个独立配置；不包含 Windows、移动端或其他实体设备验收。
- **授权边界**：保留已有改动及个人数据；不提交、不推送、不发布。后续已按用户指令启动实施；Engine 业务恢复逻辑未在 Desktop 重建或改写。

## 1. 目标与完成定义

用户应能看懂为什么发生选择、正在为哪台设备选择、各候选组包含哪些设备、选择后哪些关系改变。用户必须完成所有当前待处理选择，才能继续使用主界面。

最终交付必须同时满足：

1. 选择窗口使用 Engine 提供的原因、候选名称、成员及影响；不再从当前在线状态或名单差集推算业务结果。
2. 中英文表达准确，未知、名单不完整、待确认和需要重新加入互不混淆。
3. 默认无选中项；本机移除二次确认；多项选择在同一窗口衔接；成功、失败、版本变化、断线和重启不会卡住或重复提交。
4. 有可重复生成、恢复和启动的四配置及五配置测试数据，能单独运行一个场景，也能运行全部场景。
5. 第 8 节真实多配置场景和受控展示场景全部通过，留下截图、操作记录和结果依据。接口测试、组件测试及弹窗出现均不能单独作为完整验收。
6. 使用本次源码生成的后台和 GUI 程序，验证正在运行的程序来源；测试不操作原有 a/b/c/d。
7. 交付实际运行说明和逐项结果报告。失败、跳过、环境限制均不得计为通过；存在未通过必验项时不能宣布本规格完成。

## 3. 窗口结构与文案

### 3.1 选择前

**2026-09-07 简化确认**：当本机是被移除设备时，标题直接显示“Test B 要将本机移出设备组”，
不重复展示本机名称及同义原因。两项为“退出设备组 / 保留现有设备”，各只附一句本机影响。
完整名单默认收起，通过“查看设备”展开。重新加入详情放入展开内容；二次确认只在点击退出之后出现。
其他冲突仍根据真实原因展示，不能套用退出本机的文案。此约定优先于下方初版结构描述。

- 标题明确本机，例如“为 d 选择设备组”，旁边显示“本机：d”。实际设备名称按用户内容处理。
- 原因摘要使用核实过的事实，例如“b 提出移除 c”。详情不足则用中性表达，不能替设备编造决定。
- 多个事项显示当前位置和当前待处理数量，不暗示数量永久固定。
- 候选使用现有选项卡片；普通窗口纵向排列，内容随窗口宽度换行。优先展示两组差别，再展示完整候选名单。
- 初始无选中项；确认按钮禁用。鼠标或键盘主动选择后才启用，不按当前组、远端、在线或时间先后推荐某组。
- 卡片区分“组内设备”和“选择的影响”。不把组内名单标为“已在线”或“已经可以同步”。
- 不显示“与组内设备的同步仍需确认”等笼统句子。确有影响需要提示时，指明具体设备及具体结果；不能把等待状态写成还需用户再次确认。
- 没有关闭、取消整项或稍后处理按钮；点击遮罩、按 Esc 均不能退出选择，也不能通过导航或其他主界面入口绕过。

以下仅用于表达设计；名单必须由 Engine 提供，不可硬编码：

| 本机 d 的选项 | 组内设备 | 影响 |
| --- | --- | --- |
| 接受移除 c | a、b、d（本机） | c 将不再与本机同步 |
| 保留当前设备组 | a、c、d（本机） | 与 b 的同步将暂停 |

一般历史分歧使用“保留当前设备组”“使用另一设备组”等真实适用标题，不能套用移除文案。候选更多时逐项展示，不假设永远只有两项。

### 3.2 选择后与本机移除

- 明确突出选中项；确认按钮使用可解释的动作，如“接受移除 c”“保留当前设备组”“使用所选设备组”。
- 本机将被移除、退出或需要重新加入时，显示明确影响；要求单独二次确认。此时允许“返回选择”，但不能绕过整个窗口进入主界面。
- 不得仅因成员名单没有本机就判断本机会被移除；名单可能不完整。使用 `impact.localDeviceOutcome`、`requiresRePairing` 及后台的 `local_device_confirmation_required` 结果。
- 没有足够信息证明本机影响时，明确资料不足；不能制造二次移除确认，也不能默认安全。若 Engine 允许选择，按原选择协议提交并服从返回的确认要求。

### 3.3 提交、完成与下一项

- 提交后保留所选方案和原因，禁用会产生第二次提交的操作；不用无期限旋转图标代替结果。
- 网络请求完成、后台继续处理和查询最新状态是三个不同阶段。每个阶段必须可结束，并有对应错误或等待表达。
- `completed` / `already_completed` 后重新查询；只有查询确认当前事项已解决，才展示处理完成。
- 处理完成不等于所有设备已在线。仅在事实明确时显示“等待 b 确认”等具体状态，不承诺立刻恢复同步。
- 同一窗口展示结果。若还有独立事项，先说明上一项已处理和新事项的原因，再让用户点击“继续处理”进入下一项；默认不沿用上一项选择。
- 所有事项处理完毕后才提供“完成”返回主界面。后台新增事项时，以最新查询为准，不因旧的完成结果放行。
- 同一事项因重复通知或迟到资料更新，不得自动变成一次新的用户选择。若 Engine 再次给出已完成事项，记录并调查，不能由界面永久屏蔽该事项掩盖问题。
- 用户退出整个应用不视为已选择。重新打开后必须重新查询并恢复待处理窗口。

## 4. Engine 资料接入规则

唯一生成类型来源：`src/api/generated/types.gen.ts`。禁止手改生成文件或再定义一套相同业务类型。

| 字段 | 展示规则 |
| --- | --- |
| `issue.reason.kind` | 选择完整中英文句子模板；覆盖 pending_removal、different_removals、removal_decision_disagreement、diverged_history、unknown |
| `reason.changes` / `decisions` | 只引用已核实作者、目标、候选侧和决定；没有表态的设备不补写“接受/拒绝” |
| `reason.detailsComplete` | 不完整时只描述已知部分，必要时说明“部分变化详情暂不可用” |
| `choice.members` | 优先使用候选自己的名称与身份，覆盖当前组不存在的远端设备 |
| `memberDeviceIds` / `membersComplete` | 用于候选成员展示及完整性判断；不用于推断同步权限或当前在线状态 |
| `sourceDeviceIds` | 表示资料来源，不等于操作作者 |
| `impact.syncScopeDeviceIds` | 预期同步范围，不能标为当前已恢复同步 |
| `impact.pausedDeviceIds` | 显示具体暂停关系，不用当前名单差集代替 |
| `impact.pendingConfirmationDeviceIds` | 不显示泛化警告；提交后按明确事实列出等待设备，不能假设其已同意 |
| `impact.requiresRejoinDeviceIds` | 说明具体设备若要加入所选组同步需重新加入，不描述为自动加入 |
| `impact.localDeviceOutcome` | 本机影响和二次确认展示的依据之一 |
| `impact` 缺失或 null | 显示影响资料尚不完整，不当成“无影响”；不回退到当前快照自行计算 |

名字为空使用本地化的未命名设备表达；重名在本次比较范围内统一区分，不按名字合并身份。超长名字换行或提供完整可访问名称，不截掉关键影响。来自候选的名称可能是准入时名称，不能宣称一定是最新改名。

设备名只插入完整翻译模板，按普通文本渲染，不当 HTML、不翻译名称。中英文必须分别完整验收。

需要删除或替代的旧逻辑：

- 将 `memberDeviceIds` 直接称为继续同步名单。
- 用当前设备列表差集推算停止名单。
- 只从当前设备快照解析所有候选名称。
- 接受/保留仍消费旧的同一份 `currentChange` 影响预览。
- 使用第一项默认选中，或跨事项保留已选编号。
- 已被统一处理替代的重复刷新/加载逻辑；不留下平行实现。

## 5. 状态、并发与错误

状态流为：加载当前事项 → 未选择 → 已选择 → 必要时本机确认 → 提交 → 核对结果 → 已完成或继续等待 / 可恢复失败 / 资料已变化。

- 界面状态由既有 `DeviceTrustContext` 统一管理；卡片不另存一份业务关系。
- 提交使用当前 `issueId`、`choiceId`、预期 revision。更新导致选项或影响变化时使旧确认失效，提示重新核对，不自动提交替代方案。
- 同一事项仅名称等展示资料补齐时可保留仍有效的选择；任何本机结果或成员影响变化必须重新确认。
- 连点只产生一次选择请求。后台通知和提交后查询并发时，旧查询不得覆盖新状态，任何退出分支都要结束自身加载。
- `state_changed`：重新查询并让用户确认新资料；不自动重试决定。
- `pending`：提交已受理、仍在处理；显示明确状态，按现有通知和必要查询等待，不当成成功，也不持续允许重复提交。
- `re_pairing_required`：按实际返回说明下一步重新加入，不能显示仍属于所选组且可以同步。
- 请求失败或超时：结束该次请求的加载，重新查询是否已经执行；在结果未知时不宣称失败未生效，也不自动重发选择。
- 查询失败：保留已知内容并标明无法刷新，提供重试查询入口；不能清空事项并放行主界面。
- 首次打开、重新连接、后台重启和窗口重新显示时补查。恢复查询必须覆盖断线期间发生的变化。
- 请求和恢复等待使用具名、有限期限；到期留下明确可恢复状态。测试使用条件等待，不以固定睡眠、无限等待或放宽断言获取通过。

## 6. 可复用多配置 userdata

### 6.1 组织与入口

优先扩展 `e2e/run.mjs`、`e2e/run-plan.mjs` 及现有双/三配置辅助工具，先评估当前 macOS GUI 驱动能力，再添加四/五配置支持。不另造一套仅用于截图的假应用来替代真实验收。

须交付四类可运行入口，具体命令名在实现时确定并写入测试说明：

1. 生成指定场景基线。
2. 从基线创建新运行副本，并启动相应数量的独立 GUI 与后台。
3. 运行单场景或全场景测试。
4. 停止本次运行、恢复起点并保留失败证据。

场景定义、生成脚本及使用说明纳入仓库；可变 userdata、测试密钥、运行副本和截图报告放专用忽略目录。新增跟踪文档只使用仓库相对路径。

### 6.2 隔离与可恢复性

- 使用专门测试身份，配置名称带统一测试前缀、运行编号和角色；不使用原有 a/b/c/d 作为写入或清理目标。
- 一个场景的四/五份资料必须成套生成、成套恢复，保留彼此合法的身份和信任关系。不能只复制数据库、遗漏密钥及其他受管资料。
- 基线经正常停止后保存；不直接复制运行中的 SQLite 文件和缓存。基线只读，每轮测试从副本开始，不能污染基线。
- 建立清单，记录场景版本、Engine/产品版本、角色、必要文件、校验值、准备步骤和预期前置状态。重启后以实际公开查询验证基线，不仅检查目录存在。
- 同一组身份的不同副本不得同时联网运行；同场景并行执行必须重新生成独立身份，或由工具明确拒绝。
- 不复制 PID、锁、daemon.conn、端口、短期会话凭据等运行信息；临时邀请码、过期会话和地址在新运行中重新建立。
- 处理安全存储的位置和访问方式，证明副本可解锁、可重启。不得为了可复制而关闭业务加密或明文写入业务负载。
- 优先通过现有公开业务操作及 Engine 测试工具建立合法历史。禁止直接伪造已确认成员状态、改写数据库来制造“成功”。
- 旧版本基线不兼容时显式重新生成或按已验证迁移处理；不能静默修改基线。真实场景和旧资料展示样本分开管理。
- 清理只允许本次清单中、通过路径和进程归属校验的测试目标；不按宽泛进程名停止用户程序，不递归清理工作区、共享缓存或个人目录。
- 禁用系统剪贴板副作用；同步验证使用专门测试内容与公开历史/传输入口，不能覆盖用户剪贴板或泄露用户数据。

## 7. 两类测试与证据标准

**真实多配置 GUI 测试**：至少一套四配置和一套五配置，使用真实 Engine、真实本地持久化、真实后台连接及实际 Tauri 窗口。场景准备可调用现有业务接口，决定性的选择必须通过界面点击。必须检查选择后的设备关系和实际产品结果。

**受控展示与故障测试**：用于难以稳定产生的缺失资料、长名称、语言切换、请求失败、乱序刷新等，允许可控响应或故障注入。必须注明注入点，不能伪装为真实跨配置业务完成；除组件测试外还需实际窗口展示与交互证据。测试入口不得进入发布版本。

每个 case 输出：输入场景及版本、角色与程序来源、关键操作、预期与实际结果、截图位置、通过/失败、失败日志与清理结果。面向公开分享的日志和错误报告不得记录设备原始身份、用户名称或完整业务响应；必要身份映射与测试凭据只能留在受控的本地测试资料中。

截图至少覆盖选择前、选中后、提交反馈、最终结果；多事项另附衔接状态，本机移除另附二次确认。失败时保留当前窗口截图和各配置时间对齐后的脱敏日志。

## 8. 必验场景

### 8.1 真实多配置流程

| 编号 | 场景与操作 | 必须断言的结果 |
| --- | --- | --- |
| G01 | 四配置基线，两侧分别移除不同设备，接收冲突后在 GUI 选择；两个候选各从新副本运行一次 | 原因、作者和目标准确；候选及影响与 Engine 一致；最终有效成员和预览一致，互斥名单无重复 |
| G02 | 对同一次移除，一侧接受、一侧拒绝，再交换历史并处理冲突 | 只描述已有决定；GUI 可完成两种选择；结果对应所选组，不把另一事项的描述混入当前事项 |
| G03 | 本机属于被移除目标 | 本机结果明确；二次确认前不能执行；返回选择有效；确认后进入正确的退出/重新加入流程，不显示虚假同步成功 |
| G04 | 五配置场景，远端候选含当前快照不存在的设备 | 显示候选提供的真实测试名称；名单完整性正确；选择后的关系可查询并实际验证，不只断言设备名称出现 |
| G05 | 多项冲突及处理后迟到证据、第三方重复转发 | 当前问题与选择身份一致；同一窗口逐项处理；已解决事项不无故重开，新事项能说明新原因；全部完成才放行 |
| G06 | 查看选择后断开本机与后台连接，断线期间其他配置产生变化，再恢复 | 恢复后补查；旧选择失效时要求重新确认；不出现永久加载或静默放行 |
| G07 | 未处理时重启 GUI/后台；处理完成后再分别重启 | 未处理事项恢复；已完成决定保留；基线以外没有残留测试进程；已完成事项不重复要求选择 |
| G08 | 提交过程中断开连接或重启后台，制造响应未送达 | 界面结束请求等待并核对真实状态；不自动重发或误称未执行；确认已完成则显示完成，否则可明确继续恢复 |
| G09 | 基线恢复并重复运行同一场景至少两轮；四配置和五配置均覆盖 | 每轮从相同业务前置条件开始；第一次运行不污染第二次；无身份副本同时运行、无过期凭据导致假失败 |

G01/G02/G04 至少验证一个所选组内允许的设备对可通过公开发送入口传送专用测试文本，并在目标 GUI 历史中看到它；同时对预期暂停或移除关系验证公开状态和显式发送结果符合规则。不能仅凭“未收到”或“日志无错误”证明阻断成功。

G05 需在确定的恢复完成条件后，再主动触发证据重放或重启验证稳定性，不能用短暂未弹窗代替“不重复”的证据。

### 8.2 受控展示、交互及异常边界

| 编号 | 场景 | 必须断言的结果 |
| --- | --- | --- |
| U01 | reason/members/sourceDeviceIds 缺失，impact 缺失或 null | 不崩溃、不臆测原因或影响；保留可用的旧资料；资料不足不伪装为空组或无影响 |
| U02 | membersComplete=false，detailsComplete=false；分别组合完整与不完整资料 | 两种不完整独立表达；不把未知成员当作不存在，不因名单缺本机就认定本机移除 |
| U03 | 预期同步范围含待确认设备 | 卡片无笼统“同步仍需确认”；不标为立即可用；处理后仅据明确事实指出等待哪台设备 |
| U04 | 重名、空名称、远端新增名称、超长名称、含 HTML 字符的名称 | 名称对应身份、不执行 HTML、不翻译用户名称；仍能看全关键差异与动作 |
| U05 | 中文/英文；正常及窄窗口；长内容 | 至少 1100×800 和 720×600 窗口截图；无重叠或关键内容丢失；内容可滚动，确认区始终可访问；覆盖现有明暗主题 |
| U06 | 鼠标、Tab、方向键、空格/Enter、Esc、遮罩、背景导航 | 初始无选择；选择与提交可通过键盘完成；Esc/遮罩不能绕过；焦点留在窗口，全部完成后恢复到主界面合理位置 |
| U07 | 重复点击、提交与刷新竞态、旧响应后返回 | 只发一次选择；旧结果不覆盖新结果；每个终止分支清理加载；下一事项不继承 busy 或旧选项 |
| U08 | state_changed、pending、already_completed、re_pairing_required、local_device_confirmation_required | 每种结果有正确下一步；预期版本与确认语义不丢失；pending 不等于成功 |
| U09 | 查询失败、提交明确失败、超时、长时间等待 | 反馈明确，可重查或重试；未知结果先核对，不盲目重发；无无限旋转、无错误时清空事项 |
| U10 | 第一项解决后出现第二项；同一事项资料更新；下一项又包含本机移除 | 原窗口展示完成和新原因；重新选择；二次确认不跨事项复用；不得闪退后马上弹出无解释窗口 |

受控测试通过不能替代 G01–G09；真实多端成功也不能替代 U01–U10。所需 macOS 驱动不可用时须解决驱动或选择可实际操作 Tauri 的现有工具，不能将浏览器模拟通过写成桌面端到端通过。
