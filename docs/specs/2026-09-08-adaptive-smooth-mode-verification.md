## 原生窗口验证

测试使用专用 `smooth-mode-1622` 配置，剪贴板模式为 passive。普通桌面构建因工作区未准备 `uniclipd` sidecar 失败；为只验证 GUI 模式与存储，测试构建通过临时 `TAURI_CONFIG` 移除 externalBin，不更改仓库打包配置。该程序不能当作完整产品安装包。

原生测试构建文件为 `target/debug/uniclipboard`，SHA-256：`f170100ad080a0093b1b8716ff5839fb624b39c5c662f63f7a2b81f678ad17b3`。原生测试之后的修改包括其他语言文案、采样就绪条件及冗余判断清理；最终前端已重新完成全量测试和普通构建，原生证明范围仍以上述测试构建为准。

第一次测试缺少前端 WebDriver 桥；第二次在窗口刷新期间过早发命令导致连接丢失。修正测试前端与等待页面 timeOrigin 改变的条件后，第三次原生测试通过（1 项）：切换、保存、根标记应用和窗口重新加载保持同一 GUI 会话均符合预期。测试运行器仍打印缺少外部 tauri-driver 与清理模拟存储警告，但实际使用的嵌入式 WebKit 会话和断言通过、退出码为零。该结果不包含原生双窗口与完整后台业务。
