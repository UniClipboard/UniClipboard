# CLI 发送等待的虚拟时间测试规格

## 状态与目标

状态：代码与发送范围验证已完成；全量兼容验收存在例外，见验证记录。代码基线：`c4e8342e4`，核对日期：2026-10-23。

将 Go CLI 发送前的轮询、截止时间和发送准入条件放入进程内虚拟时间测试，避免为这些决策反复启动多个 daemon、配对和实际等待。生产与测试必须执行同一份等待算法，真实进程协作仍由端到端测试验证。

本文已吸收交接中的需求，实施无需依赖临时交接文件。执行顺序见[实施计划](2026-10-23-cli-virtual-time-plan.md)。

本轮包含：

- 使用标准库 `testing/synctest` 的进程内测试，以及对应的持续集成步骤。
- `tests/e2e/tests/send_connect_wait.rs` 的覆盖迁移，以及保留场景使用本地邀请目录服务所需的夹具调整。

## 3. 行为契约

### 3.1 预算起点与终点

- 输入解析和标准输入读取完成后，`runSend` 为非零 `--connect-timeout` 创建一个绝对 `deadline`。
- daemon 就绪与目标连接复用这个值，后续阶段不得重新用“现在 + 完整预算”计算截止时间。
- 获取租约处于这段准备流程内；本轮不新增网络请求取消或超时机制。
- `--connect-timeout 0` 不执行目标等待；`--resend` 即使预算非零也只准备 daemon，不执行目标等待。
- 预算限制发送前准备，不是文件传输或最终 dispatch 的总时限。真实 HTTP 调用耗时沿用现状，不能承诺整个命令严格在预算时刻返回。

例如，60 秒预算在 daemon 准备后已消耗 57 秒，目标始终离线时只再等待 3 秒。超时文案仍显示用户指定的 60 秒。

### 3.2 每轮顺序

1. 查询 daemon 的 `/peers` 快照。
2. 查询失败则结束等待，允许最终发送报告权威错误。
3. 使用现有 `targetReadiness` 判断；满足条件则结束等待。
4. 仍未满足时报告等待状态，再检查是否已到截止时间；到期则失败。
5. 睡眠 `min(500ms, max(deadline - now, 0))`，重复查询。

必须保持这个顺序。因此在截止时间恰好到达时，本轮快照若已就绪仍允许发送；查询失败仍交给最终发送处理。已经超过截止时间但快照未就绪则不再睡眠。不得改成循环入口先判超时。

### 3.3 在线条件

| 输入与状态 | 等待结果 |
| --- | --- |
| 指定一个或多个 `--peer` | 所有指定 ID 的 `connected` 均为 true 才就绪 |
| 指定 ID 不在快照 | 继续等待，原因为 `unknown device` |
| 指定 ID 在快照但未连接 | 继续等待，原因为 `offline` |
| 未指定 ID，至少一个已配对设备连接 | 就绪 |
| 未指定 ID，有已配对设备但全部离线 | 等待，报告已配对设备数量 |
| 未指定 ID，没有已配对设备 | 结束等待，由最终发送报告结果 |

指定 ID 的判断沿用当前代码，只检查该 ID 是否存在且已连接；不擅自补充 `isPaired` 条件。未指定 ID 时，只考虑已配对设备。

### 3.4 错误、输出与副作用

- `daemonclient.FromEnv()` 失败仍立即报错，不能与 `/peers` 查询失败混为一类。
- 查询失败不自动等于发送成功；最终结果由原 dispatch 路径决定。
- 超时继续返回 `exitcode.Error`，保留错误与提示文案、设备排列顺序及 stderr 输出；JSON 模式失败时 stdout 保持为空。
- 等待循环只读查询，不能导入、保存、发送内容或重试 dispatch。
- 准备成功后，生产编排只调用一次所选发送路径；失败或取消不调用。批量文件路径内部现有的逐文件操作不在“一次”的计数范围内。
- 保留控制租约持有至发送完成、失败时释放、Ctrl-C 处理和现有信号语义。本轮不重新设计取消后的后台协程生命周期；若提取暴露独立问题，另列有证据的缺陷，不夹带行为修复。
- 在线快照不是最终投递保证；查询后设备掉线仍由 daemon 的发送结果解释，不引入自动补送。

## 4. 设计

### 4.1 所有权与接口

| 组件 | 职责 |
| --- | --- |
| daemon / Engine | 设备快照、最终发送结果、内容持久化与实际传输的权威来源 |
| CLI 查询适配函数 | 用现有 daemonclient 读取 `/peers`，返回现有 `peerSnapshot` 列表 |
| CLI 共享等待函数 | 接受查询函数、设备 ID、绝对截止时间及等待状态通知函数；执行唯一轮询算法 |
| CLI 输出适配层 | 创建和清理 spinner，按等待结果渲染现有错误与提示 |
| CLI 发送编排 | 准备成功后选择并执行一次发送路径，持有和释放租约 |
| 测试 | 提供内存快照和操作计数，运行真实等待函数与发送准入编排 |

查询边界使用包内函数参数，例如 `func() ([]peerSnapshot, error)`；优先复用现有类型，不为一次查询引入通用客户端接口。等待结果须区分允许继续与超时，并携带原等待原因；查询失败沿用“允许继续”，不扩张为新的用户错误。

输出通过窄的等待通知函数连接原 spinner；测试提供内存观察器。生产输出适配层负责在所有退出路径清理 spinner。不要在虚拟时间测试里启动真实终端渲染、替换全局 stdout/stderr 或修改包级客户端变量。

在 `send.go` 提取最小的共享发送准入函数：接收准备操作与所选发送操作，统一处理准备失败、取消、租约释放和成功后的单次调用。生产的输入分类与发送类型选择留在原责任位置，发送操作闭包调用现有文本、单文件、批量文件或 resend 路径。测试必须调用这个生产编排函数计数，不能在测试里自行写一遍“等待成功则发送”。

为验证共享预算，准备流程只在实际 I/O 边界注入 daemon 准备操作和目标查询；测试记录传入的同一 `deadline`，模拟前置阶段消耗预算，再进入共享等待函数。按实际函数关系选取最少的包内参数，不建立通用依赖容器或公开 API。

### 4.2 虚拟时间边界

每项测试在 `synctest.Test` 内创建截止时间、通道和所需协程。生产仍调用普通 `time` API，无须新增 `Clock` 接口、生产虚拟时钟开关或第三方时钟依赖。

测试快照优先由 `time.Since(start)` 决定。例如在虚拟 4 秒之前返回离线、之后返回在线；这样无需依赖两个定时协程在相同时刻的调度顺序。并发测试通过测试范围内通道或 `synctest.Wait` 建立同步关系，禁止忙等和真实睡眠。

真实 socket、HTTP 服务器、Rust 子进程、系统信号与系统凭据不进入虚拟时间测试。它们仍交给真实 E2E；仅将现有 E2E 外包一层 `synctest` 不能提速。[Go 官方文档](https://pkg.go.dev/testing/synctest)说明了虚拟时间推进及可判定阻塞的限制。

## 5. 进程内验收矩阵

建议统一测试名前缀 `TestSendVirtualTime`，允许以子测试表达矩阵。下表编号用于覆盖记录，不要求一行对应一个顶层测试。

| 编号 | 场景 | 必须断言 |
| --- | --- | --- |
| V01 | 指定设备开始即在线 | 不睡眠；发送操作一次 |
| V02 | 指定设备在 4 秒时上线，预算 60 秒 | 虚拟 4 秒检测就绪；只发送一次 |
| V03 | 指定设备始终离线，预算 60 秒 | 虚拟 60 秒超时；发送零次；保留等待原因 |
| V04 | 两个指定设备仅一个在线，随后另一个上线 | 部分在线时不发送；全部在线后一次；等待原因只含未就绪 ID |
| V05 | 指定设备不存在 | 到期超时，原因保留 `unknown device` 与输入顺序 |
| V06 | 未指定设备，一台已配对在线、另一台离线 | 不等待另一台，发送一次 |
| V07 | 未指定设备，所有已配对设备离线 | 到期超时，数量正确；发送零次 |
| V08 | 未指定设备，无已配对设备；或仅未配对设备在线 | 无配对时交给 dispatch；有配对且都离线时不被未配对在线设备放行 |
| V09 | 首轮或若干轮后查询失败 | 停止查询，dispatch 一次，其错误原样传播，不渲染目标超时 |
| V10 | daemon 客户端准备失败、租约获取失败 | 原退出码，发送零次；不调用目标查询 |
| V11 | 60 秒预算，准备阶段消耗 57 秒 | 传递同一 deadline；目标离线只再等 3 秒；发送零次 |
| V12 | 到期时快照就绪、到期时仍离线、到期时查询失败 | 分别允许发送、超时、交给 dispatch；不改变顺序 |
| V13 | 剩余 250ms 或截止时间已过去且目标离线 | 前者只睡 250ms；后者不睡；均不额外等待 500ms |
| V14 | `--connect-timeout 0` 与 `--resend` 对应的生产准备分支 | 不查询目标；后者保留 daemon 准备预算 |
| V15 | 准备被取消或失败、成功发送后返回错误 | 前两者发送零次；后者调用一次且不重试；租约按原所有权释放 |

V14 必须覆盖生产使用的分支，不能只测试手工传入的固定布尔值。预算创建位置、参数到等待开关的接线另由保留的真实 E2E 共同验证。

## 6. 真实 E2E 保留与迁移

基线 `send_connect_wait.rs` 定义 14 项真实测试，其中 3 项仅 Unix 编译；平台测试数量必须按实际发现结果记录。

| 现有函数 | 本轮处理与覆盖承接 |
| --- | --- |
| `unknown_target_times_out_at_the_deadline_without_sending` | 保留短预算真实输出/退出码验收；长预算算法由 V03、V05、V12、V13 承接 |
| `zero_timeout_dispatches_immediately_like_before` | 保留参数与真实 dispatch 接线；V14 补充分支覆盖 |
| `file_send_waits_for_targets_before_dispatch` | 保留文件路径也经过等待的接线 |
| `late_connecting_peer_receives_exactly_one_copy` | 保留真实 daemon 重启、重连、实际收到一份内容的验证 |
| `permanently_offline_peer_gets_nothing_after_the_deadline` | 保留超时后重启接收端仍无内容的验证 |
| `interrupt_while_waiting_for_a_device_exits_without_sending` | 保留真实 SIGINT 与无发送验证，Unix 限定 |
| `absent_daemon_is_started_within_the_budget` | 保留真实 daemon 自动启动 |
| `daemon_that_never_starts_ends_at_the_deadline_with_exit_5` | 保留启动失败的退出码与预算验证，Unix 限定 |
| `file_send_json_keeps_stdout_machine_readable` | 保留真实文件传输及 JSON 输出验证 |
| `every_listed_peer_must_connect_before_dispatch` | V04、V05 接管条件与原因组合；通过后删除该三节点 E2E |
| `one_connected_device_is_enough_without_the_peer_flag` | 保留真实广播与在线/离线结果验证；V06 接管精确等待断言 |
| `all_paired_devices_offline_times_out_without_the_peer_flag` | V07 接管数量、超时和零发送；真实离线副作用由保留的离线 E2E 承接，通过后删除 |
| `resend_does_not_wait_for_devices` | 保留真实 resend 接线；V14 补充 |
| `file_send_shows_real_byte_progress_on_a_terminal` | 保留真实终端字节进度，Unix 限定 |

因此计划目标为 14 项减至 12 项源级 E2E，最终以实际发现数量为准。不得用虚拟时间测试替代实际投递、无补送或终端行为证据。

保留场景的配对准备复用 `tests/e2e/src/rendezvous.rs` 的 `LocalRendezvous`，通过 `TestDaemon` 的现有 rendezvous 覆盖参数传入所有参与节点；服务对象必须活到所有节点结束，重启后保留同一地址。只为本套场景增加必要的可配置夹具入口，不全局改变其他调用者的默认行为，不复制邀请服务。

本地邀请目录只消除配对准备对生产目录服务的依赖，不代表整个 P2P 测试完全离线。公网目录服务冒烟与这些常规场景分开运行并单独报告；现有 Python 差分 `pair` 依赖生产服务，本轮保留并明确标注，不能计入“本地常规组”。

## 7. 验收与证据

- 所有 V01–V15 对应测试通过，执行到共享生产等待与发送准入代码；生产中没有旧轮询备用路径。
- 包含虚拟 60 秒超时的测试组，预编译后二进制单轮执行墙钟时间小于 1 秒；不含编译，不以虚拟时间推断墙钟耗时。
- 同一测试组连续 20 次全部通过，禁用缓存；另跑竞争检测。20 次要求不指全套昂贵 E2E。
- 记录主机、Go 版本、提交、发现的用例数量、逐轮执行耗时和失败次数；记录原真实等待测试集与迁移后真实集各自的耗时、夹具耗时及网络模式。
- 基线与改造后在同一机器、相同构建模式和并发配置下采样；若基线配对失败，按失败报告，不把失败提前退出当作提速。
- 输出、退出码、JSON、真实取消、租约和传输验收通过；Python 差分按现有规则执行，公网准备失败独立列出，不能记为全绿。
- 持续集成 `cli-go` 作业实际运行新测试。当前作业只有 vet 与构建，新增测试若未接入就不能宣告完成。
- 本轮不新增持久化数据、凭据或遥测。证据只记录脱敏的测试标识、耗时与结果，不收集邀请字符串、令牌或真实用户内容。

已有独立示例曾证明虚拟 60 秒可以快速完成；该记录不是本仓生产代码或整套 E2E 提速的验收证据。
