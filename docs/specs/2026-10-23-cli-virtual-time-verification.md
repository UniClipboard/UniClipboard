# CLI 虚拟时间测试验证记录

## 环境与范围

日期：2026-10-23。源码基线：`c4e8342e4`。环境：Linux arm64、Go 1.27.1；Rust 使用 debug 构建，daemon 启用 `uc-daemon/e2e-rendezvous`。

生产改造为无意改变行为的结构提取：原等待逻辑同时承担 daemon 查询、轮询决策和终端输出，导致只能通过真实进程验证时间条件。现在查询与准备 I/O 使用包内函数参数，`pollSendTargets` 是唯一轮询实现，`dispatchSend` 是生产和测试共享的发送准入编排。旧轮询和 `prepareSendDispatch` 路径已替换，没有并行备用实现。

行为及覆盖要求以[规格](2026-10-23-cli-virtual-time-spec.md)为准，实施顺序见[计划](2026-10-23-cli-virtual-time-plan.md)。

## 真实 E2E 与性能比较

原始 Go CLI 使用 `go build -overlay` 从 HEAD 的两个原始发送源文件构建；其余源码与当前构建一致。原始 Rust E2E 二进制在夹具改动前构建并保留。测试二进制在临时 HOME、独立 XDG 目录运行，禁用系统剪贴板。

第一次原始组运行的自动启动场景因基线 CLI 同级缺少 daemon 而失败；补齐同级 daemon 后，单独重跑通过（1.62 秒墙钟）。第一次整组运行 383.67 秒，12 项通过、2 项失败（包含默认跳过的终端进度项）；另一失败发生于配对准备并报告 `invitation_unavailable`，尚未证明是公网或时序根因。该结果不能当作全通过基线或直接用于完整加速倍数。完整修正基线已通过：14/14，399.75 秒（同样包含默认跳过的终端进度项）。

终端字节进度测试原本受 `UC_E2E_RECORD_ONLY` 门控；默认成功仅表示跳过，不能作为已验证终端进度的证据。本次保持该已有门控。

本地目录夹具改动后的原始 14 项 E2E 已全部通过，357.64 秒（包含默认跳过的终端进度项）。据此删除 `every_listed_peer_must_connect_before_dispatch` 和 `all_paired_devices_offline_times_out_without_the_peer_flag`；由 V04、V05、V07 承接等待组合，保留实际离线投递验证。最终 12 项组已复验通过，244.40 秒。

Rust/Go 全量差分发现 Rust 开发 CLI 与用户 Go CLI 的现有命令名称、`--dev`、生命周期输出差异。另用原始 Go CLI 与改造后 Go CLI 执行四组发送差分，以区分本次回归与实现间既有差异；四组发送差分全部一致，每实现 86 步。

原始执行工件位于忽略目录 `target/cli-virtual-time/` 与 `target/compat/`，不提交邀请或凭据。

## 验收边界

发送范围的实现、覆盖迁移和本地验证已完成。全量 Rust/Go 差分未通过验收，原因是
未改动模块已有帮助、生命周期、搜索和升级输出差异；本次提前结束其完整遍历。
不得据此标记整个 CLI 全量兼容通过。恢复全量基准维护属于独立工作。

上述实现不改动 Engine、daemon API、持久化、凭据、遥测或传输规则。用户随后已授权提交、创建 PR，并在发布后重新运行 CLI E2E；发布后结果另行记录。
