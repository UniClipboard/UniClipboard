# v0.19.1 升级到当前版本兼容性测试计划

## 文档状态

- 状态：macOS ARM 与 Windows ARM64 适用范围已完成；U01-U12、U14-U21 通过，U13 不适用
- 日期：2026-08-14 至 2026-08-15
- 测试环境：macOS ARM 实机、Windows 11 ARM64 虚拟机
- 升级起点：UniClipboard v0.19.1 官方发布版
- 升级目标：当前分支构建版本

## 测试目标

验证真实用户从 v0.19.1 原地升级到当前版本后，可以继续使用已有数据、身份、空间和设备关系，不需要重置、重新配对或重新创建空间。

本计划同时验证新旧版本短期共存、分批升级、升级中断、重复启动和已移除设备等高风险情况。

## 完成标准

全部必测场景通过，并满足以下结果，才可认定升级兼容性通过：

- 用户不需要重置应用、重新配对设备或修改原口令。
- 本机设备身份和所在空间保持不变。
- 剪贴板历史、收藏、文件和设置没有丢失。
- 设备列表没有重复设备。
- 已移除或已处于不同空间的设备不会重新出现在当前设备列表中。
- 所有设备完成升级后，可以继续双向同步。
- 新旧版本共存期间，不会形成错误的设备关系或继续不安全的同步。
- 升级过程被中断后，再次启动可以继续完成，且不会损坏数据。
- 重复启动不会重复执行迁移或产生重复记录。

任何必测场景失败，均不得以其他场景通过代替。

## 测试基础

### 旧版本来源

使用 GitHub Release `v0.19.1` 的官方发布包，不从旧源码重新构建。

本机自动测试使用：

```text
uniclipboard-cli-0.19.1-aarch64-apple-darwin.tar.gz
```

下载后必须先校验官方 `SHA256SUMS.txt`。当前已确认该文件包含对应发布包，发布包摘要为：

```text
df8966aa0b462c69de8a304a99f71228ea2c9119fa3a327a33bb48df9b27b4e6
```

### 数据隔离

- 自动测试使用独立且唯一的测试档案。
- 不使用或修改现有 a、b、c 档案。
- 每个场景保存独立的数据目录、日志和结果记录。
- 同一个场景升级前后必须复用同一数据目录，模拟真实原地升级。
- 除专门验证清理流程外，不删除旧版本生成的任何文件。

### 测试方式

测试分为两层：

1. 命令行自动测试：使用 v0.19.1 官方命令行程序和后台程序创建真实旧数据，再替换为当前版本继续运行。
2. 桌面界面验收：使用 v0.19.1 官方应用创建代表性数据，再安装当前构建，实际检查解锁、历史页和设备页。

仓库现有历史兼容测试固定的是 `v0.20.0-alpha.6`，不能作为 v0.19.1 已通过的证据。本计划需要新增独立的 v0.19.1 基线。

## 升级前基线

每个场景在替换程序前，都必须记录以下信息：

- 旧版本号。
- 本机设备标识。
- 所在空间标识。
- 当前成员数量、名称和设备标识。
- 历史记录总数。
- 代表性文本、图片和文件记录。
- 收藏状态。
- 全局同步、自动同步、文件同步及按设备设置。
- 当前在线和离线设备。
- 当前已移除设备及尚未完成的设备变化。
- 数据目录中关键文件清单和大小。

涉及同步的场景还必须证明接收端已经实际保存测试内容，不能只记录发送端成功数量。

## 统一检查项

每个场景完成后，至少检查以下结果：

### 身份与空间

- 本机设备标识与升级前一致。
- 空间标识与升级前一致。
- 不出现新的本机设备副本。
- 不要求重新邀请或重新加入原空间。

### 数据

- 历史总数与预期一致。
- 代表性文本内容完全一致。
- 图片可以显示并导出。
- 文件可以读取，文件名和内容正确。
- 收藏状态保持。
- 搜索仍能找到升级前记录。
- 删除和恢复等基本操作仍可用。

### 设置

- 全局同步开关保持。
- 自动同步开关保持。
- 文件同步开关保持。
- 每台设备的发送和接收设置保持。
- 网络和中继设置保持。
- 界面设置保持。

### 设备关系

- 当前成员数量正确。
- 设备名称和标识正确。
- 在线、离线、需要升级、不同空间和已移除不会相互混淆。
- 历史设备关系不会把已移除设备补回设备列表。
- 所有设备升级后，成员关系最终一致。

### 同步结果

- 新内容从发送端发出后，接收端实际保存并可读取。
- 已移除设备不会收到新内容。
- 不同空间设备之间不会收到新内容。
- 仍在同一空间的设备可以继续同步。
- 文件同步通过接收端文件实际可用来判断，不能只看发送端结果。

### 安全与日志

- 错误口令不会改变原数据。
- 日志不包含口令、密钥、剪贴板正文、完整文件名或文件路径。
- 迁移失败时保留可恢复状态，不静默重置。
- 不产生新的明文业务数据文件。

1. U01：最小原地升级。
2. U02：历史和文件兼容。
3. U06：双设备同时升级。
4. U07：单边升级。
5. U08：第二台完成升级。
6. U12：已移除设备不会恢复。
7. U15：升级中断恢复。
8. U16：重复启动稳定性。
9. U19：正式安装目录升级。
10. U20：命名档案隔离。

第一轮任何一项失败，应停止发布判断，保存双方数据目录和日志后排查。

### 第二轮：扩展兼容性

执行 U03、U04、U05、U09、U10、U11、U13、U14、U17、U18 和 U21。

## 自动测试建议

在现有 `tests/e2e` 基础上扩展，不另建测试框架：

- 为 v0.19.1 增加独立且带校验值的固定发布基线，不替换现有 v0.20.0-alpha.6 基线。
- 新增 `upgrade_from_v0_19_1.rs`，承载单设备、历史、重启和数据保持场景。
- 在成员兼容测试中增加明确使用 v0.19.1 的双设备、三设备和已移除设备场景。
- 先使用旧版本程序创建数据，再停止旧后台并用当前程序在同一档案上启动。
- 等待异步结果时使用有截止时间的轮询，不使用固定时长等待作为通过依据。
- 同步通过必须由接收端的持久化结果证明。

## 桌面界面验收

自动测试通过后，至少执行一次真实界面升级：

1. 安装并启动 v0.19.1 官方应用。
2. 创建空间并设置口令。
3. 添加文本、图片、文件和收藏记录。
4. 与第二个隔离档案配对并完成双向同步。
5. 记录本机身份、成员列表和历史数量。
6. 完全退出旧版本及其后台程序。
7. 安装并启动当前构建。
8. 使用原方式解锁。
9. 检查历史页的内容和数量。
10. 检查设备页只展示当前空间成员。
11. 检查旧设备不会因历史关系重新出现。
12. 启动另一设备的当前版本，验证双向同步恢复。
13. 重启两端，再次检查身份、历史和设备列表。

## 不属于通过证据的结果

以下结果不能单独证明升级成功：

- 当前版本能够启动。
- 后台健康检查通过。
- 发送端报告已发送。
- 设备显示在线。
- 数据库文件仍然存在。
- 单元测试或编译通过。
- v0.20.0-alpha.6 的升级测试通过。

升级兼容性必须由 v0.19.1 真实数据原地升级后的身份、数据、设备关系和接收端结果共同证明。
