送达状态组件 · 4 套重设计原型

基于 BoardUI v2 语义 Token 与真实 Engine Operation 状态（可切换场景、宽度、明暗主题，并点击「重试」体验交互）

核心改进点： ① 替换误用的文件图标，区分设备类型与外部渠道（如 WeType）； ② 收口到与上方属性卡片一致的圆角容器与语义色阶； ③ 异常项就地提供 重试 入口，不再让用户折返底部 Dock； ④ 覆盖进度、等待确认、对端已接收、已发送、未接纳、失败与重启回退全状态。

方案对比与 mygo / desktopkit 落地评估

方案 视觉与交互核心 多设备 / 窄抽屉表现 推荐适用倾向 mygo 实现复杂度
方案 A
分组状态卡		 圆角卡片容器 + 设备/渠道图标 + 右侧语义胶囊 + 行内重试 清晰稳定；4 台以上需滚动，但单行语义最明确 想要「稳妥升级」、零学习成本、与现有详情页无缝融合 低（复用 SubtleCardSurface + 图标映射 + 新 DeliveryRow）
方案 B
折叠概览条		 健康态折叠单行；异常/传输态自动展开 + 分段微进度条 极佳；常规浏览几乎不占详情页纵向高度 高频浏览纯文本/图片、希望详情页极简克制 中（需在 ui.Local 中维护单条展开态 + 分段条绘制）
方案 C
双列磁贴网格		 与上方 3 列 Fact Card 同构的 2 列磁贴，异常/进度自动跨列 2~4 台极紧凑；窄抽屉下长主机名较易省略 偏爱 Bento 卡片美学、设备数通常在 2~4 台 低-中（ui.Row 两两分组或固定两列布局）
方案 D
异常优先分组		 异常/传输用高亮焦点卡，已送达收敛为轻量横排胶囊 极佳；即使 6~8 台设备也保持低高度和高信噪比 经常多端群发、最关心「哪台没收到、立刻重试」 低（按状态拆分两个切片渲染即可，无需折叠状态）
